## (a) Confirmed defects

**A1. The T265 regression test is a tautology — it compares a function with itself.**
`src/differential.zig:269-272`: `engineKoNewGeneric` is literally `return solverKoGeneric(...)`. The test `"ko key (T265): fixed engine rule agrees with solver"` (differential.zig:336-342) therefore compares `solverKoGeneric` against an alias of itself over all 2x2/3x2/3x3 boards. It never imports `gtp.zig` and gives **zero** coverage of the actual fixed code (`gtp.zig:717-744` `koAfterCapture`). If gtp's ko rule regresses tomorrow, this test stays green. This is precisely the failure mode codified in AGENTS.md's QA-023 rules ("A positive control must exercise the instrument under test, not a parallel one"). The commit message for 626ec55 admits the real invariant ("key-agreement in the differential harness") is "still owed by T265" — but the misleadingly-named test that exists now reads as if it were that invariant.

**A2. differential.zig is not wired into any build or test target.**
build.zig's test step covers only main.zig, oracle_v2_accept, vb_table, vb_fixpoint, vb_graph (build.zig:95-158); main.zig's test block imports 17 modules but not differential (main.zig:151-169). So the T257 agreement harness — including its null control, seeded-defect control, and both T265 ko tests — never runs under `zig build test`. It runs only if someone types `zig test src/differential.zig`. Same for `oracle_v2_consumer_load.zig`. A harness that doesn't run is not a control.

**A3. The "first end-to-end regression fixtures" (626ec55) are not runnable regressions.**
`docs/evidence/ORACLE-V2/human-game-{1,2}.gtp` contain `genmove W` lines, so replay requires the artifact `untracked/oracle-v2/oracle-4x4-v2.wzo2` — which is gitignored and per AGENTS.md dies on a fresh clone. No zig test references them (grep "human-game" in src/ → nothing) and nothing in build.zig or tools/ pipes them. Contrast the older fixture done right: `regressions/4x4-history-blunder.gtp` is artifact-independent (fixed transcript) and mirrored by the in-suite test at gtp.zig:1663. The T265 fixtures are evidence documents, not regression tests, and the commit message oversells them.

**A4. Assertion-free green tests and a silently-vacuous negative control in vb_fixpoint.zig.**
- `"I7 DTT sanity on 3x2 artifact"` (vb_fixpoint.zig:502-509) computes, prints `terminals_bad=52`, and asserts **nothing** (comment defers to the 4x4 test).
- `"I9 anchors on 2x2 artifact"` (vb_fixpoint.zig:523-530) prints `match=false` and asserts nothing.
- The deferred-to definitive check, `"I7 DTT sanity on 4x4 basicko-tie artifact (must fail)"` (vb_fixpoint.zig:511-521), opens `data/oracle-4x4-basicko-tie-area.wzo` with `catch return` — the file is gitignored (confirmed via `git check-ignore`), so on any fresh clone this must-fail control silently passes vacuously, with no skip marker. Under the project's own "never trust a green test" doctrine, all three are violations.

**A5. The ko rule exists in ~14 hand-written copies and zero production implementations.**
rules.zig deliberately excludes ko (rules.zig:100 "No ko rule here"). The `liberties == 1 and friendly == 0` ko condition is copy-pasted in: exp6_solve.zig:285,575,909 (three copies *inside one file*), exp6_hchain_audit.zig ×3, exp5_solve.zig ×2, t129_exp7_4x4.zig ×2, exp4_solve.zig:305, exp7_census.zig:241, qa023_brute_2x2.zig, qa023_probe.zig, qa023_pinrule.zig, differential.zig:243, and now gtp.zig:742. T265 happened because gtp.zig had the fifteenth, *different*, copy — and the commit itself calls it the "third defect of that family after T178 and T193." Three producer/consumer key mismatches from the same root cause is a confirmed systemic defect, not a smell.

## (b) Judgment on the two recent fixes

**T265 ko fix (626ec55): content-correct, verified honestly, but a patch, not a principled fix.** The new gtp.zig logic (gtp.zig:717-744) does match exp6_solve's rule, the fix was verified by replaying both human transcripts (misses 14→0, 12→0), and the evidence doc (docs/evidence/ORACLE-V2/human-games-2026-08-02.md) is a model of honest root-cause writing — it even names the missing invariant ("the key the engine constructs must equal the key the builder would write"). But the fix *adds another copy* of the rule instead of extracting a shared `koAfterCapture` into rules.zig or exp6_solve, the promised invariant is still absent, and the regression tests are A1/A3 above. The lookup-miss fallback that fabricated terminal rows is still there (gtp.zig:165-169) — now loud (WARNING + stats_misses counter) but still silently converts an off-manifold state into a fake terminal instead of refusing. Family defect #4 remains structurally available.

**T262 claimlint fix (74ebe60): sound, and I found no siblings of that bug class.** `owned_file` is duped once (claimlint.zig:1554-1555) and used in all four C7 append paths. Lifetime survey: the only other walker (Index.build, claimlint.zig:369-388) already dupes `e.path` at :385; checkFindings (:1791-1802) passes `e.path` only into the now-duping parseFindingsFile; register rows/`resolve()` cache keys are slices into the CLAIMS.md buffer, which is page_allocator-backed and never freed for the program's life — safe in a short-lived CLI. `body` at :1795 leaks per findings file; harmless here.

## (c) Systemic weaknesses

**S1. src/ is a junk drawer with a good engine inside.** Roughly 20k of 47k lines are top-level one-off experiment binaries (exp4/5/6/7, qa023_×4, t129, five censuses, ko_probe, signcross, psk_divergence, eyeprune_×2, audit_2x2_mismatch, check_colex, v0_test), plus a stray extensionless notes file `src/notes_on_depth_6_24bitz`. No directory boundary separates engine from experiment.

**S2. The de facto production solver is named exp6_solve.zig.** The import graph proves promotion without rename: `oracle_v2_build.zig`, `oracle_v2_consumer_load.zig`, and `differential.zig` all import it; its header still reads as an EXP-6 worker deliverable with `tools/runner` invocation instructions (exp6_solve.zig:19-33). Meanwhile retro.zig — the file AGENTS.md's "one writer per engine file" rule protects — is the *old* PSK engine.

**S3. The duplication doctrine ("one production + demoted fixtures") is only half-real.** The doctrine genuinely holds in two places: `qa023_brute_2x2.zig` is a real shared oracle (imported by 7 files), and differential.zig registers exp6-vs-rules implementation pairs for area_score/legality/capture/encode. But exp4, exp5, exp6_hchain_audit, exp7_census, t129, qa023_probe/pinrule/smoke, and all five census files are imported by **nothing** — they are unwired copies runnable only by hand, i.e. copy-paste drift wearing the doctrine as cover. And the one operation where a mutual oracle mattered most (the ko rule, A5) has no production implementation at all.

**S4. retro.zig main() is a 27-branch undocumented env-var dispatcher** (retro.zig:4358-4553: RETRO_CENSUS/PARALLEL/RULES/KILLCENSUS/CYCLE/BRACKET/E2/E2SANITY/B1_LOFIX/CORE/PLY/CMP/DEPSVAL/DIAG/ANCHOR/3X3/SAVE/CONSIST×4/VERIFY/REPLAY/6X3/4X4/PLAIN...), plus a behavior kill-switch buried inside engine logic — `getenv("RETRO_NOSINGLEKO")` evaluated inside `solveSingleKo` per call (retro.zig:765). The abandoned kill-X% rule is still wired into the Bellman loop (retro.zig:276-289, Tables.kill_pct at :136) — honestly commented as abandoned, but live code.

**S5. verify_battery.zig bypasses std.Io for raw libc with fragile casts.** `std.c.open(@ptrCast(p), ...)` on a `[]const u8` (verify_battery.zig:85, :148) assumes NUL-terminated backing memory — true for argv today, undefined the day a constructed path is passed. `openOutput` silently falls back to stdout when the output file fails to open (:86), and `Output.write` ignores the write() return (:67).

**S6. Unexplained anomaly in the passing suite:** `zig build test` stderr contains repeated `failed command: ... /test --listen=-` blocks for 3-4 test binaries while the Build Summary reports "11/11 steps succeeded; 242/242 tests passed", exit 0 (reproduced twice, seeds 0xd7a161f6 / 0xa43ba777). Something in those binaries exits abnormally after reporting results. Worth one look — a suite whose runner prints "failed command" on success will train people to ignore that string.

## (d) Genuine strengths

- **rules.zig is exemplary** — arguably the best-tested 1000 lines in the repo: cross-validation against the independent 5x5 stack (rules.zig:400-460), a deliberately differently-structured second Benson implementation with documented structural divergences (rules.zig:569-806), an exhaustive attack-DFS test of **Benson's theorem itself**, not just the port (rules.zig:462-540), and 4x4 stratified regression sweeps that really run in-suite (4,840,525 positions at k≤8, confirmed in test output).
- **`zig build test` covers the core engine, not just utilities.** main.zig's test block (main.zig:151-169) pulls 17 modules including retro, oracle, gtp, artifact2, superko, solve; retro.zig has convergence/L≤H/colour-inversion-swap/finisher tests (retro.zig:4558-4615). 242 tests, ~30 s.
- **Negative controls mostly exist and mostly run:** vb_table synthetic violation tests (vb_table.zig:815, :961, :1005), oracle_v2_accept's A6 three named corruptions each mapped to the check that must catch it (oracle_v2_accept.zig:1191-1285), differential's null/seeded-defect/known-bad trio (differential.zig:152-215 — though see A2). The doctrine is institutionalized, with the exceptions listed in A1/A4.
- **Honest comments that correct themselves in place** — the kill-edge comment records its own earlier falsehood with the measurement that refuted it (retro.zig:127-135); gtp.zig documents exactly where `choose` is unsound and why (gtp.zig:249-271).
- **Error-handling discipline is deliberate, not sloppy:** loud invariant panics (`"TT: inconsistent value for a position"` solve.zig:156, seq-pool backstop solve.zig:138, MAX_HIST gtp.zig:207, MAX_SWEEPS retro.zig:332); `error.Budget` as a genuine error path (oracle.zig:203-205); the `catch unreachable` at retro.zig:3999 re-applies a move already validated in the same loop — justified. `catch unreachable` on `bufPrint` into sized static buffers throughout gtp.zig is fine.
- **Instrumentation earned its keep:** the per-miss WARNING with full state (gtp.zig:168) plus stats counters is what made the T265 diagnosis a one-transcript read — the evidence doc credits it explicitly.
- Everything wired compiles (zig build exit 0) and all 60 src files pass ast-check; there is no bit-rot in the *built* surface. The unwired experiment files' compilability is unverified except where imported (exp6_solve, qa023_brute_2x2 compile transitively).

**Headline for synthesis:** the core is strong and the epistemics are unusually honest, but the project's two newest wounds share one cause — the ko/key rule has no single owner — and the T265 remediation added a copy, a tautological test, and unrunnable fixtures instead of the invariant its own commit message says is owed.
