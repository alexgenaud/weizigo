## (b) Systemic weaknesses

- **The hub's presumption of staleness points the wrong way.** AGENTS.md:111 says if the dated docs disagree with PROGRESS, "PROGRESS is stale and that is a bug." The dated docs are frozen 2026-07-28 snapshots; every disagreement I found (QA-027 predicted 100%, now FALSE-AS-SCOPED; the roadmap's pinning design superseded by ADR-0020; QA-028 already withdrawn) is *absorbed progress*, not PROGRESS staleness. The rule as written sends bug-filers at the healthiest document — while the surfaces that actually rot (boards trees, indexes) have no staleness rule at all. There is a clean staleness gradient: register (hours) → PROGRESS (mixed) → boards trees (days-to-weeks) → indexes (stale + hardcoded lies), and the reading order recommended to newcomers is roughly the reverse.
- **The register's cell format doesn't scale to adjudication.** The `QA-023` row (`CLAIMS.md:578`) is a ~700-word palimpsest with nested bold warnings, three dated amendments, and an embedded "DO NOT MARK THIS ROW FALSE" plea. Honest, but a single-cell essay is unreviewable and un-diffable; the machine-readable layer is becoming a prose layer with pipes in it.
- **A permanently-red gate is a dashboard, not a gate.** claimlint exits 1 and has since 2026-07-28 (`CLAIMS.md` §8 records exit 1 as "recorded debt"). Nothing halts on it; the Argus ratchet is the real control, and it has already been exceeded (A8) without visible response.
- **Verification is syntactic where the failures are semantic.** C6 cite-tags, C7 status diffs, and the calibrations are excellent instruments, but every confirmed contradiction above (A2, A3, A4) passes all of them, because tags matched statuses while the *sentences* contradicted each other. The project's own `AUDITOR.md:27` names this residue; this audit confirms it is where the live defects are.
- **Denominator babel at 4×4.** Four "state" counts circulate — 51,419,046 reachable triples (H1-CENSUS), 99,133,036 checked states (T104/A3), "147M states" (`CLAIMS.md:445`, `PROGRESS.md:190`), 48,636,330 side-slots — with no reconciliation table, in a project that wrote a model reconciliation for the 21.32/21.33/21.27% family (`boards/4x4/EPISTEMIC.md:223-243`). Smell, not defect: they are probably all correct under different state definitions, but a reader cannot verify that.
- **The taxonomy is real but the vocabulary leaks.** PROVEN/CLAIMED/FALSE-AS-SCOPED is genuinely enforced at the register level (I found no status a sampled evidence file contradicts), but headline verbs escape it: "solved" (PROGRESS §8.1), "verified genuine" for a build whose artifact fails inversion. The `narrowed` column tracks retreat-by-reclassification; nothing tracks advance-by-vocabulary.

## (c) Done genuinely well

- **claimlint is the best epistemic instrument I have seen in a repo of this kind.** Zero-skip parsing, three edge kinds including the novel `n:` derives-from-negation with inverted propagation (`CLAIMS.md:91-111`), every check mapped to an incident the project actually suffered, and it ships with in-run calibration (six known-bad, three known-good fixtures, all caught/silent correctly). It caught, in this audit, most of what I then confirmed manually.
- **Tier-A evidence packages are exemplary.** `docs/evidence/T13/probe-reimplementation-2026-07-30.md` is the standout: independent Python re-implementation from the method description alone, three independent routes to the same twelve numbers, and it *strengthens the falsification against itself* (12 → 154/508) while carefully explaining why the original count was order-dependent. GLOBAL-S4, GLOBAL.H1-CENSUS, and the ORACLE-V2 M4a documents state commands, seeds, acceptance criteria, and denominators.
- **Refuted proposals are preserved, not deleted.** The `WZO2-4X4-VALID` row (`CLAIMS.md:503`) records T212's reasonable-when-made PROVEN proposal alongside its refutation, with the moral spelled out: "passing every check we had did not make the artifact valid, because no check we had tested completeness." Same pattern in `CODE.WZO2-UNRUN`'s supersession banner. This is rare and valuable practice.
- **Losses are inventoried, not papered over.** `CLAIMS.md` §7 tables every destroyed evidence file with a disposition (LOST / RECOVERED / RECOVERABLE), and claimlint distinguishes recorded losses from dangling citations.
- **Declared coverage gaps.** The register names the documents it did *not* sweep (`CLAIMS.md:185-190`) — the honest form of incompleteness.
- **The `narrowed` / `wrong-answer-pass-rate` columns are genuinely original diagnostics**, and the meta-finding ("4 of 5 repeatedly-narrowed claims are now FALSE" — claimlint check A) is the kind of self-knowledge most projects never compute.

**Bottom line for synthesis:** the epistemic apparatus is real, not aspirational — statuses are enforced, evidence for recent PROVEN rows exists and supports the claims, and falsifications are absorbed with unusual honesty. Its failure modes are second-order: generated surfaces that lie about their own provenance (A1), semantic contradictions invisible to syntactic checkers (A2-A4), a conformance rot at the newest pipeline edges (A6, A9), and an 82% Tier-B PROVEN debt that the tooling reports but no process retires (A10).
