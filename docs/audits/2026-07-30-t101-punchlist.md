## 1. `GLOBAL.S2` — in-deg 10 — Benson's unconditional-life theorem

**Claim (`CLAIMS.md` §2.1):** "Benson's unconditional-life theorem holds on
every finite goban." Evidence cited: `CONCEPTS.md:10-12`; `4x3/EPISTEMIC.md:25`.
Dependents (6 named in the register, formal in-deg 10): `GLOBAL.ADR0004-TERM`,
all `S2-impl` rows, `GLOBAL.ADR0006-EYE`, terminal detection on every goban,
the eye-prune, H5(b). This is the **widest** PROVEN row in the tree — every
terminal score and the eye-prune both hang from it.

**Why it is PROVEN and what evidence is missing.** This is an *external
mathematical theorem* (D. B. Benson, "Life in the Game of Go", and the
unconditional-life algorithm, 1976). The project did not prove it; it cites
it. The implementation's correctness is a **separate** set of rows
(`3x3.S2-impl` PROVEN, `4x4.S2-impl` / `4x3.S2-impl` UNTESTED) — those are not
what `GLOBAL.S2` asserts. What is missing is a committed record of *which*
theorem, *which* paper, the formal statement, and the finite-goban scope
argument.

**Cheapest committed-evidence path — a literature note, no build, no run.**

1. Create `docs/evidence/GLOBAL.S2/PROVENANCE.md` containing:
   - the formal statement of Benson's unconditional-life theorem (a set of
     strings is unconditionally alive iff it passes Benson's two-region test);
   - the citation: Benson's 1976 papers (full bibliographic reference, and a
     note that the algorithm is reproduced in many Go-programming sources,
     e.g. the Tromp–Taylor and Kishimoto literature the project already
     cites);
   - the finite-goban scope argument (the theorem is goban-shape-agnostic;
     Benson's test is local to strings and their eye regions, so it lifts to
     any finite goban without modification);
   - the explicit hand-off: "`GLOBAL.S2` is the *theorem*; correctness of the
     `rules.zig` implementation is the separate `*-S2-impl` rows and is not
     discharged here."
2. Optionally, commit a one-page reproduction of Benson's algorithm in
   pseudocode so the citation is self-contained.
3. No probe, no run, no artefact — the row is mathematics. Cost: **~1 hour**,
   no build.

**What this does NOT close.** The `S2-impl` rows (the implementation) stay
UNTESTED at 4×4/4×3 — those are tree-shake L4 (`S2-impl` at 4×4 and 4×3, a
Benson implementation regression battery, cheap, artefact-independent). The
cheapest *sound* upgrade to this row is to run L4 alongside it; that closes
both the theorem citation and the implementation regression in one cheap wave.

## 2. `GLOBAL.INVSYM` — in-deg 9 — colour inversion + dihedral symmetry

**Claim (`CLAIMS.md` §2.2):** "Colour inversion: `value(−pos,−side) ==
−value(pos,side)`; for bound tables `L(−pos,−side) == −H(pos,side)`; dihedral
transforms never change score or sign." Evidence cited: `0009:102-107,148-157`;
`0008:48-51,54-60`; `AGENTS.md:75-77`. Dependents (formal in-deg 9, all
`e:`): every symmetry battery, orbit propagation, the E2 policy fix, all
dihedral batteries, `GLOBAL.P2`.

**Why it is PROVEN and what evidence is missing.** Two halves: (a) a
mathematical fact — the Bellman map commutes with the colour-swap involution
because the Go rules are colour-symmetric and the score is Black-positive by
convention, so `value` is an odd function of `(pos, side)`; dihedral symmetries
commute because the rules and the area score are rotation/reflection invariant;
(b) an implementation fact — the engine actually respects this, evidenced by
the symmetry batteries and orbit propagation. The argument is in the ADRs
(`0008`, `0009`); the batteries run in the codebase (`src/audit_2x2_mismatch.zig`
is the dihedral-mismatch detector, `src/chainability.zig` propagates orbits).
What is missing is a committed **proof note** plus a committed **battery run
log**.

**Cheapest committed-evidence path — a proof note + an existing-tool run log.**

1. Create `docs/evidence/GLOBAL.INVSYM/PROVENANCE.md` with:
   - the colour-inversion proof: the Bellman update is a pointwise min/max of
     child values plus the pass value; under `(pos, side) → (−pos, −side)` the
     child set maps bijectively and the optimum flips sign, so the fixpoint is
     odd (one paragraph of algebra, citing `0009:102-107`);
   - the bound-table corollary `L(−pos,−side) == −H(pos,side)` (same argument,
     applied to the two fixpoints separately);
   - the dihedral argument: the legal-move generator and the area score are
     invariant under the goban's dihedral group, so the fixpoint commutes with
     every symmetry (citing `0008:48-51,54-60`);
   - the explicit scope: this is the *property*; engine compliance is the
     battery below.
2. Run an existing symmetry battery on the smallest committed-permissible
   artefact (2×2 then 3×2 — both have committed-permissible reference tables)
   and commit the raw stdout alongside the PROVENANCE. The natural instrument
   is `src/audit_2x2_mismatch.zig` (the dihedral-mismatch detector) for the
   dihedral half, and an orbit-propagation check from `src/chainability.zig`
   for the colour-inversion half. If no single tool exercises both, run the
   two and commit both logs.
3. Cost: **a few hours** — the proof is one page and the tools already exist;
   no new build beyond invoking an existing one under `tools/runner`.

**What this does NOT close.** It does not test symmetry at 4×4 (no
committed-permissible 4×4 artefact yet — that is the Track A / writes-off
regen, a rank-1 load-bearing unknown in `CLAIMS.md` §4.2, far from cheap). The
2×2/3×2 battery is the calibration set; certifying the property there is the
honest scope for this row.

## 3. `GLOBAL.FP1` — in-deg 8 — Knaster–Tarski least/greatest fixpoint

**Claim (`CLAIMS.md` §2.2):** "L is the least and H the greatest fixpoint of
the Bellman map (Knaster–Tarski, monotone map, seeded from `−N`/`+N`)."
Evidence cited: `CONCEPTS.md:25-30`; `0009:53-61`. Status: **PROVEN (as
mathematics)**. Dependents (formal in-deg 8): all per-goban `FP1` rows,
`GLOBAL.C3`, `GLOBAL.BRACKET`. Note `4x4.FP1` is the *per-goban acceptance*
row and is UNTESTED (checks 1–2); it is a **different** row from this one and
is **not** discharged here.

**Why it is PROVEN and what evidence is missing.** Pure mathematics: the
Bellman map `T` on the finite lattice `[−N, +N]^(positions × sides)` is
monotone (each update is a pointwise min/max of child entries and a constant,
so `x ≤ y ⇒ T(x) ≤ T(y)`), and the iterates seeded at the bottom `−N` and top
`+N` converge in finitely many sweeps (`GLOBAL.FP3`, also PROVEN, also Tier B
debt at in-deg 4) to the least and greatest fixpoints by Knaster–Tarski. The
argument is in `0009`; what is missing is a committed proof note + the
textbook citation.

**Cheapest committed-evidence path — a proof note, no build, no run.**

1. Create `docs/evidence/GLOBAL.FP1/PROVENANCE.md` with:
   - the lattice: `[−N,+N]^(positions × sides)`, finite, complete;
   - the map: the Bellman update `T = min/max over children + pass`, and a
     one-line monotonicity proof (`x ≤ y` componentwise ⇒ every child optimum
     and the pass value are ordered ⇒ `T(x) ≤ T(y)` componentwise);
   - the seeds: `−N` is the bottom, `+N` the top; iterates from the bottom are
     ascending, from the top descending;
   - the conclusion by Knaster–Tarski (cite Tarski 1955, "A lattice-theoretical
     fixpoint theorem and its applications", or any standard reference) that
     the bottom-seeded iterate converges to the least fixpoint `L` and the
     top-seeded to the greatest `H`;
   - the finite-termination hand-off to `GLOBAL.FP3` (a separate row): on a
     finite lattice the iterate stabilises in finitely many sweeps, which is
     what makes the seed/zero-change acceptance checks of `4x4.FP1`/`4x3.FP1`
     well-defined.
2. No probe, no run. Cost: **~1–2 hours** to write the proof cleanly.

**What this does NOT close.** The per-goban `FP1` acceptance rows
(`4x4.FP1`, `4x3.FP1`) and their sub-checks (`4x4.FP1-C1` seed, `4x4.FP1-C2`
zero-change, `4x4.FP1-C3` V0/V1 identities). Those are the tree-shake's **L1**
("seed + zero-change checks — post-hoc reads of existing logs/artifact, check
3 already passes, hours") and are the *empirical* half of the fixpoint story;
`GLOBAL.FP1` is only the *mathematical* half. L1 is the natural companion and
should be dispatched in the same wave.

## 4. `GLOBAL.S4` — in-deg 5 — area scoring implemented correctly

**Claim (`CLAIMS.md` §2.1):** "Area (Chinese) scoring is implemented
correctly; the score is a pure function of the terminal snapshot." Evidence
cited: `CONCEPTS.md:20-21`; `0003:13-16`. Dependents (formal in-deg 5):
every terminal score, `GLOBAL.ADR0004-TERM`, `GLOBAL.ADR0006-EYE`.

**Why it is PROVEN and what evidence is missing.** The implementation lives in
`src/score.zig` (`area_score`) and `src/terminal.zig`, and there is **already**
a cross-validation measurement row, `CODE.S4-XVAL` (`CLAIMS.md` §2.1):
"`rules.zig` cross-validated: 500 random gobans vs `terminal.zig`, 1000 random
moves vs `state.armies_from_move`, all equal" (`0008:63-66`). `CODE.S4-XVAL`'s
`dependents` column explicitly names `GLOBAL.S4` and `GLOBAL.S3a`. So the
evidence **exists** — it just is not committed under `docs/evidence/GLOBAL.S4/`.
This is the only one of the five where the probe has already run and already
fed the row; the debt is purely a commit-the-output debt.

**Cheapest committed-evidence path — commit the existing cross-validation, or
add an independent reference scorer (tree-shake L5).**

Two options, cheapest first:

- **Option A (cheapest, ~hours): commit what already runs.** Locate the
  `CODE.S4-XVAL` harness (the 500-goban / 1000-move cross-check described in
  `0008:63-66`), run it, and commit the probe source + raw stdout under
  `docs/evidence/GLOBAL.S4/PROVENANCE.md`. This moves the row to Tier A by
  replicating the existing measurement. It is a *self-consistency* check
  (engine vs engine), so it does not satisfy the standing
  independent-re-implementation rule (QA-023 lesson: the only method that has
  ever found a defect here is re-implementation in another language).
- **Option B (the sound cheap option, ~half a day): tree-shake L5.** Write a
  ~40-line **independent Tromp–Taylor area scorer in Python** (the ruleset is
  ~10 lines of pseudocode in Tromp–Taylor 2008), run it on a fixed corpus of
  terminal snapshots (the same 500 random gobans, or a hand-picked set
  including the eye/dame edge cases), and commit the Python source + the
  corpus + the comparison log under `docs/evidence/GLOBAL.S4/`. This is the
  route the tree-shake recommends (`§3.1 L5`: "area-scoring battery vs an
  independent reference scorer (tiny Tromp–Taylor scorer in another
  language) … removes the ⬜ᴵᴺᴴ under every terminal value on the two biggest
  gobans").

**Recommendation:** Option B. It costs only marginally more than A and is the
only one that would catch a defect in `src/score.zig` rather than confirm one.
A is acceptable as a stop-gap to clear the linter; B is the honest evidence.

**What this does NOT close.** The 4×4/4×3 `S4` rows (`4x4.S4`, `4x3.S4`) are
UNTESTED (`⬜ᴵᴺᴴ`, self-declared inheritance) — they assert the *same*
scorer is correct at the bigger gobans. An area scorer is goban-size-agnostic
by construction, so a single Tromp–Taylor cross-check on a size-stratified
corpus (2×2, 3×2, 4×4 snapshots) discharges all three rows at once; that is
the cheap generalisation and should be the scope of Option B.

## 5. `GLOBAL.AUDITOR` — in-deg 5 — the #2 self-consistency auditor is the standing gate

**Claim (`CLAIMS.md` §2.4):** "The `RETRO_CONSIST` self-consistency auditor is
the standing pre-commit gate; passing is necessary, not sufficient (a solver
can be self-consistent at a wrong fixpoint)." Evidence cited:
`consistency-audit.md:6-23`; `AGENTS.md:63-67`; `0013:117-122`. Dependents
(formal in-deg 5): `3x2.F1`, `3x2.F3`, all `F4` rows, `4x4.M6` reading 2, the
`GLOBAL.H5` gate. Status: PROVEN, with `narrowed = 1` (the necessary-not-
sufficient qualifier is the one narrowing).

**Why it is PROVEN and what evidence is missing.** The auditor is implemented
in `src/retro.zig` (`consistBoard`, around l. 2973) and its methodology is
documented in `docs/research/consistency-audit.md:6-23`. The standing gate
(`AGENTS.md:63-67`) is "zero minimax-identity violations on 3×2 exhaustive +
the deepest-N 4×4 sample." That gate has been run many times (it is the
instrument that found the `ko_ref ≥ d` bug, ADR-0013); what is missing is a
committed run log under `docs/evidence/GLOBAL.AUDITOR/`. The 3×2 exhaustive
run is **seconds** of wall time.

**Cheapest committed-evidence path — a seconds-long re-run + a PROVENANCE
note. The single cheapest item on this list.**

1. Create `docs/evidence/GLOBAL.AUDITOR/PROVENANCE.md` stating:
   - the claim's scope explicitly: the auditor is a **necessary** gate
     (zero violations ⇒ no proof of a bug; ≥1 violation ⇒ proof of a bug),
     not a sufficiency witness — a solver can be self-consistent at a wrong
     fixpoint;
   - the instrument: `consistBoard` in `src/retro.zig`, with the line range;
   - the standing gate definition from `AGENTS.md:63-67` (3×2 exhaustive +
     deepest-N 4×4 sample);
   - the methodological citation `consistency-audit.md:6-23`.
2. Run the 3×2 exhaustive pass under `tools/runner` (seconds):
   `tools/runner -- zig run -O ReleaseFast src/retro.zig` (or whichever
   entrypoint invokes `consistBoard(3, 2, …, 0)` for exhaustive mode), and
   commit the raw stdout. The `0` max-checks argument selects exhaustive
   mode per the source (`if (max_checks != 0) … SAMPLED`).
3. **Optional but cheap upgrade:** if a 4×4 checkpoint is locally available,
   also run the deepest-N 4×4 sample and commit its log. This is not required
   to clear Tier A — the 3×2 exhaustive run is the standing gate's calibration
   axis and is the run that has caught every defect to date.
4. Cost: **under an hour** — a seconds-long run plus a one-page note.

**What this does NOT close.** The auditor's *sufficiency* is a separate
question (the row itself states passing is not sufficient); a green run does
not promote any of the auditor's dependents from CLAIMED to PROVEN. It also
does not commit the deepest-N 4×4 sample unless step 3 is taken. The point of
this evidence is that the **gate itself** is durable and re-runnable, not that
any particular artefact passes it.
