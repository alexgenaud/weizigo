# weizigo — source module map

**Status: module map (accurate 2026-08-23). Not a strategy, goal, or status document.**

This file answers one question: *what lives where in the source tree.* It is
regenerated by hand and is **not** a "living document" in the status sense — the
living surface is `bin/managent resume` (composed at read time). For strategy,
goals, and epistemic status read the durable hub instead:

- `docs/epistemic/PROGRESS.md` — the narrative hub (what was tried, what failed, what is open).
- `docs/epistemic/CLAIMS.md` — the claim register (statuses + evidence + dependencies).
- `docs/epistemic/roadmap-2026-07-28.md` — the ruleset decision and roadmap.
- `docs/decisions/` — ADRs (append-only). The active semantics is
  **ADR-0020 (loopy-game fixpoint, basic ko + TIE=0)**; ADR-0022 makes bracket
  resolvers pluggable.

The source tree is `src/` — 107 Zig files, ~106k lines (2026-08-23). Most files
are one-off experiment/instrumentation programs; the load-bearing kernel is
small. This map names the load-bearing modules and groups the rest by family.

## Build & test

`build.zig` builds one executable (`weizigo`, entry `src/main.zig`), one
`engine` re-export module (`src/smd1_engine.zig`), and a `test` step that
aggregates the test suite. `src/version.zig` is generated at build time by
`tools/gen-version.sh`. Per-module tests still run via `zig test src/<file>.zig`.

## Generation 1 — the 5×5-hardcoded reference stack (validated ground truth)

Fixed `[25]i8` gobans; sign = colour, magnitude = army flag. This is the
project's validated forward-search reference; the generic stack is
cross-validated against it.

| module | concern |
|---|---|
| `state.zig` | goban representation & move application (army flags); symmetries; encodings (`blind`/`seq`/`view`). |
| `terminal.zig` | scoring & life: `area_score`, `benson_alive`, `is_settled`. |
| `superko.zig` | positional-superko `History` (game-line stack, `repeatsIndex` for GHI). |
| `solve.zig` | the validated forward search: to-terminal minimax + superko + `ko_ref` GHI caching + ADR-0006 eye-prune + `(blind,seq)` transposition table. Now the finisher/cross-check, not the oracle builder. |
| `persist.zig` | TT checkpoint codec (distinct from the `.wzo`/`.wzo2` artifacts). |
| `zobrist.zig` | standalone hashing tables (kept for future data-model work). |
| `util.zig` | sentinels / output helpers. |

## The new-rule build — loopy-game fixpoint (ADR-0020, basic ko + TIE=0)

The **active target**: a well-defined mathematical object — the limit of the
Bellman operator on `(board, side, ko_point, passes)` — computed through 4×4.
See PROGRESS.md §4, §7.4 and ADR-0020 for what this means and does not mean.

| module | concern |
|---|---|
| `exp4_solve.zig` | 2×2 / 3×2 under the new rule — the falsification gate. |
| `exp5_solve.zig` | 3×3 under the new rule — the first anchor comparison. |
| `exp6_solve.zig` | 4×4 under the new rule — the fixpoint tables. |
| `exp6_hchain_audit.zig` | independent audit of the EXP-6 H-chain (is H=+16 at the root genuine). |
| `exp7_census.zig` | certified-fraction census under basic-ko + TIE=0. |
| `artifact2.zig` | **WZO2 artifact format** (oracle-v2 M1 design, frozen at G2) — the full Markov-key table. |
| `oracle_v2_build.zig` | builds the WZO2 artifact from the fixpoint tables. |
| `oracle_v2_accept.zig` | acceptance checks (colour-inversion, round-trip, calibration, reproducibility). |
| `oracle_v2_consumer_load.zig` | loads a WZO2 artifact for consumers. |

## One-off experiment & instrumentation programs (not enumerated)

The remainder of `src/` is per-task measurement and audit programs —
`tNNN_*.zig` (task instruments), `qa023_*.zig` (QA-023 probe chain), and
census/divergence harnesses (`differential.zig`, `chainability.zig`,
`seedctl.zig`, `ko_census.zig`, `kostate_census.zig`, `symcensus.zig`, …).
Each is a standalone `zig run` program recording a number or falsification for
its own task; none is part of the kernel. They are named by task ID and should
be read alongside their findings file under `findings/`.
