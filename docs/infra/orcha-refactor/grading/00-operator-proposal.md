# Grading design — OPERATOR'S PROPOSAL, as written

**Author:** the operator, 2026-08-20. **Status:** proposal. Recorded verbatim and
unmerged, so the adjudicator sees it as written. Seat feedback is a separate file
(`01-seat-feedback.md`); Fable may adopt either, both, or a third path.

> I would like to propose another ask on future race grades with
> singular-unique-output-file: suggest metrics/aspects/skills/characteristics for each
> model-artifact pair, score each model-artifact on each metric, and rate how important
> this metric is for this artifact type. Where scores are 0-10 and ten is always best and
> importance is 0-10 where 0 is unimportant and 10 is more important.
>
> It might be too complicated to compile all metric types and ask all models to
> re-evaluate with all or a selections of metrics. Or maybe models can choose which
> metrics are important (for themselves) and re-evaluate all model-artifacts again.
>
> Or at least we might consider the accumulation of metrics to suggest on future grading.

## What the proposal establishes

1. **Metrics are emergent, not imposed.** Each grader proposes the metrics it thinks
   matter, rather than filling in a schema handed down in advance. This follows the
   operator's earlier position that we do not yet know what to measure and will discover
   the dimensions while trying.
2. **Score and importance are separate axes.** 0–10 for how good the artifact is on a
   metric; 0–10 for how much that metric matters *for this artifact type*. So "did well"
   and "mattered" never collapse into one number.
3. **Metrics accumulate.** Even if a full re-evaluation across all proposed metrics is too
   costly, the accumulated metric vocabulary informs later grading rounds.
4. **Optional second round.** Graders may re-evaluate all artifacts using metrics they
   consider important — either the full union or a selection.
