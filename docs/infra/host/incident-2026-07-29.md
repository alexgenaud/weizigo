# Host incident — 2026-07-29 02:33–02:45 (kernel panic, watchdog timeout)

**Owner:** Orchestrator (MiniMax-M3). **Date:** 2026-07-29. **Model of
record:** MiniMax-M3. **Status:** root-caused, durable.

## Summary

At 2026-07-29 02:35:57 the host kernel called `panic()` on CPU 0
(`MACC0` cluster) with the string:

```
panic(cpu 0 caller 0xfffffe0049315d8c):
  watchdog timeout: no checkins from watchdogd in 91 seconds
  (1066 total checkins since monitoring last enabled)
```

The system rebooted at 02:45:04 (9 min downtime). `untracked/msg/`
survived (git working tree, not tmpfs); no project artifact was corrupted;
all in-flight agent processes died with the kernel.

## Causal chain (corrected root cause)

The proximate cause was a `zig` compiler process running out of memory budget
during a 02:32–02:33 rebuild burst of `bin/weizigo-oracle`. The
`JetsamEvent-2026-07-29-023323.ips` artifact (446 KB, written 02:33:23,
four minutes before the panic) records the active process set at the moment
Jetsam took its snapshot:

| process | RSS | lifetime peak | CPU | note |
|---|---|---|---|---|
| `zig` (pid 92604) | **12.5 GB** | **21.8 GB** | 16 s | the proximate hog, 5× the next largest |
| `weizigo-oracle` | ~250 MB | — | — | the regression loop in the 02:27–02:33 logs |
| `weizigo-qa023-smoke-2x2` | — | — | **4,493 s = 75 min** | likely spinning (smoke test from Fable's earlier session) |
| `SmartGo` | 2.4 GB | — | — | the GTP client driving the regression |
| system free | **~46 MB of 48 GB** | — | — | the budget was gone |

The panic's compressor info is the *consequence*, not a separate cause:

```
Compressor Info: 45% of compressed pages limit (OK) and
                 100% of segments limit (BAD)
                 with 50 swapfiles and OK swap space
```

**Chain:** zig compile blew the budget (12.5 GB resident, 21.8 GB peak) →
system-wide thrash with ~46 MB free → `watchdogd` starved 91 s → Apple silicon
watchdog fired → kernel `panic()` on core 0 (where the watchdog runs).

**Honest caveat:** the blowup did **not** reproduce at clean HEAD `c63b678`
after the panic. Cold `zig build`, `zig build test`, isolated `zig build-exe`
of `src/v0_test.zig` and `src/oracle.zig` all peaked at ≤ 555 MB. The fatal
invocation was either unusual (the ad-hoc `bin/weizigo-oracle` rebuild with
dSYM in the 02:32–02:33 window is the best candidate) or the compiler ran
away on an already-thrashing host. **No evidence the EXP-9 H5a diff itself
causes a compiler blowup.**

## Initial misdiagnosis (corrected)

The Orchestrator's first report (channel 017) ranked Spotlight/APFS
reindexing first, then Ollama, then concurrent zig compilations. That
ranking was wrong. The correct ordering, given the Jetsam evidence, is
**zig compile as the proximate cause, with the rest as contributing factors
at most**. The 446 KB Jetsam file is the load-bearing artifact and 017
missed it. 018 (Dabir / Fable 5) and 019 (Orchestrator) record the
correction. The role-collapse note (Fable 5 writing as Dabir in 018) is
also recorded.
