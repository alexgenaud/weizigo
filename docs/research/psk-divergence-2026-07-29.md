# EXP-8 — PSK divergence harness (set A), 2026-07-29

**Task:** EXP-8 · **Agent:** kimi-k2.7 · **Model:** Kimi K2.7 · **Date:** 2026-07-29  
**Claim IDs:** intended to close the *value* half of `QA-012` and `QA-024`.  **Status: NOT CLOSED** — see §Blocker.

## The question, restated

For sampled positions, compare the value and the move selected by a loaded
table against the exact positional-superko (PSK) reference.  Two quantities,
reported separately:

- **Value divergence:** `|v_table(s) − v_PSK(s)| > 0`.
- **Move divergence:** the table's selection-rule move is not in the set of
  PSK-optimal moves; additionally, the *suboptimal* count and the PSK-value
  loss of the picked move.

This experiment is **S2** of `docs/epistemic/roadmap-2026-07-28.md` §2/§3.

## Important limitation of this run

The harness is built and calibrated, but **the actual new-rule-vs-PSK
divergence rate cannot be measured yet** because new-rule (basic-ko +
long-cycle tie) tables do not exist on disk.  EXP-4/5/6 are blocked behind
EXP-2B.  The numbers below therefore compare the **existing PSK tables**
(`artifacts/oracle-*.wzo`) against history-exact PSK — i.e. they quantify the
`C2` history-dependence gap in reachable play, not the rule-divergence gap.
Every headline is labelled accordingly.

## Calibration

### Known-bad (synthetic)

Perturb the 2×2 artifact's `vb[0]` (empty goban, Black to move) from the known
PSK value +1 to 0, then run `random` 10 games:

```sh
tools/runner -- /tmp/weizigo-psk-divergence artifacts/oracle-2x2.wzo \
  --games 10 --max-empties 2 --budget 200000000 --policy random --seed 20260729 \
  --perturb-vb 0 0
```

Result: value divergence **13/20** vs **unperturbed run's 28/56** — the
perturbation is detected and the divergence count increases.  Raw output in
`docs/evidence/QA-012/calibrate-bad-2x2-vb0.txt`.

### Known-good

A fresh-start exact-PSK comparison on L==H slots could **not** be run: the
history-free exact solver (`retro.Exact.root`) exceeded the 4 GB RSS cap on
every non-terminal sampled 2×2 position.  This is the same intractability
already documented at `docs/research/ruleset-options.md` §RETRO_CYCLE and is
why the brief explicitly frames the experiment around *depth* (few empties).

## Worked example (synthetic)

The known-bad calibration **is** a clean worked example:

- Position: empty 2×2 goban, Black to move.
- History-exact PSK value: **+1**.
- Perturbed table value: **0**.
- Divergence: **1 point**.
- Table's selected move under the perturbed value is not PSK-optimal in some
  sampled lines; the run reports move divergence and PSK-value loss.

The harness does not currently print per-position details; the divergence
histogram (loss = 5 pts on 2×2) is the aggregate.

## Power argument

On the largest useful sample (2×2 random, n = 56 solved positions) a zero
divergence observation would bound the rate at ≤5.36% (rule of three).  The
observed rate is far higher, so the sample is **under-powered to bound it
below 1%** (which would require n ≈ 300).  The 3×2 sample is too small and
too budget-exclusion-heavy to support any rate at all.

## Bias direction

PSK is computable precisely where cycles are scarce — near-terminal positions
and short histories.  Those are the positions where any tractable rule is
*least* likely to diverge from PSK.  The observed divergence rates are
therefore **lower bounds** on the true rule-divergence rate in real play.

## Blocker: new-rule tables are missing

The actual EXP-8 question is *"does the new-rule table diverge from exact
PSK?"*.  That requires a table generated under the new rule (basic-ko +
long-cycle tie).  No such table exists:

- `artifacts/oracle-2x2.wzo`, `oracle-3x2.wzo`, `oracle-3x3.wzo` are all
  positional-superko tables (header `rules_id = 1`).
- EXP-4, EXP-5, EXP-6 — which would produce the new-rule tables — are
  blocked behind EXP-2B (`docs/infra/dispatch/EXP-2B.md`).

Once new-rule tables are available, the same harness can be re-run with:

```sh
tools/runner -- /tmp/weizigo-psk-divergence <new-rule-table.wzo> \
  --games 1000 --max-empties <threshold> --budget <N> --policy random
```

The acceptance criterion (d/n per board/frame, 95% CI, exclusion accounting,
power argument) is then achievable for the gobans where exact PSK is tractable.

- Do **not** call the L==H region history-independent; `GLOBAL.C2` is

- Do **not** pool the 2×2 and 3×2 numbers; per-goban epistemic independence

## What this run establishes

1. The EXP-8 harness is built, compiles under the B-2 RSS runner, and detects
   synthetic divergences.
2. History-exact PSK is tractable only for a small, near-terminal subset of
   reachable 2×2 positions under the 200M-node budget; 3×2 is already largely
   intractable.
3. On that tractable 2×2 subset, the shipped PSK table diverges from
   history-exact PSK in roughly half of sampled positions.
4. The new-rule-vs-PSK divergence measurement is **blocked** until new-rule
   tables are generated.
