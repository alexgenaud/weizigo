## 2. Why this comparison is finally legitimate

Every previous anchor comparison this project made was **weak evidence
presented as strong**. `critique-2026-07-28.md` §3, verbatim in substance:
weizigo played PSK, MIGOS II played basic ko + long-cycle ties, these are
*different games*, they happened to agree at 3×3 and 4×4, and they **provably
disagree at 2×2 and 3×2**. So "3×3 = +9 matches the published anchor" has,
until now, been agreement between two different games on a goban where the
difference does not bite.

**EXP-5 is different in kind, not in degree.** EXP-2 proved, and EXP-4
validated at 2×2 and 3×2, that the rule being solved here is the same game the
anchor was computed under — van der Werf & Winands' MIGOS II ruleset, quoted at
`retrograde-3x3.md:224-245`: Chinese/area scoring, "since superko is not used",
balanced long-cycle repetition scored as a long-cycle tie. Matching +9 then
means what an anchor match is supposed to mean.

### Two honesty constraints

1. **It is legitimate only if EXP-2's ruleset formalisation actually is MIGOS
   II's.** EXP-2's A2 decision: basic-ko definition is formalisation (i) —
   single-stone ko capture shape only, the standard basic-ko rule. EXP-2's A5
   decision: value domain is integers with TIE=0 for long cycles, V =
   median(L, TIE, H). The published MIGOS II description is a sentence, not a
   specification. Where choices had to be made: the ko formalisation follows
   `src/ko_census.zig:isKoCapture`'s definition (single-stone capture, single
   liberty on the capturing stone); the long-cycle verdict is a constant tie
   (0) rather than a scored position; the value rule is median-pin, not the
   falsified v1 `L<H⇒T` rule.

2. **An anchor match is one number.** It confirms the root, not the table.
   Do not upgrade "matched +9" into "the 3×3 table is correct." The
   brute-force cross-check covers 50 late-position states (≤1 empty point,
   passes≥1) with 50/50 agreements, but this is a spot check, not an
   exhaustive verification.

## 3. Tie-vs-score disambiguation

3×3 has 9 points; with komi 0 the area score is always **odd** (all area
scores are reachable: −9 through +9). TIE=0 is **outside** the natural value
set, so a tie is unambiguously identifiable.

| determination | value |
|---|---|
| root (empty, B) | **scored +9** (L==H==9) — NOT a tie |
| root (empty, W) | **scored −9** (L==H==−9) — NOT a tie |
| tie states total | 5,738 / 73,758 (7.78%) |
| pin census | L==H=68,350, pin_T=1,248, pin_L=2,080, pin_H=2,080 |

The root is a genuine forced win: Black can force a terminal position worth
exactly +9 by area score, without relying on a long cycle. The TIE value
appears only at states where neither player can force termination —
approximately 7.78% of the reachable state space.

**The pin_L/pin_H symmetry (2,080 each) is a colour-inversion consistency
check:** pin_L (TIE < L, pinned to L) equals pin_H (TIE > H, pinned to H),
as required by `value(-pos,-side) == -value(pos,side)`.

## 4. How this differs from prior attempts

### 4.1 RETRO_BRACKET already "matched" +9 — by containment, not computation

`ruleset-options.md:209-213`: 3×3 empty-goban bracket **[2, 9]**, width 7,
marked "✓ in-bracket" against the +9 anchor. That is a bracket 7 wide out of
a 25-point range (−9 to +9 plus ties) containing the anchor; `ruleset-
options.md:223-227` states outright that the empty-goban bracket is WIDE and
that the L/H method "says little about *it specifically*". **Containing +9
is not computing +9.** This run produces the number +9, not a bracket.

### 4.2 The existing 3×3 artifact is PSK and fresh-start-only

`artifacts/oracle-3x3.wzo` — 65.7% single-score, 8,698 ko-sensitive slots. Its
values are **not** a reference for this experiment. Both roots are +9 by
coincidence, but the two tables differ below the root wherever the PSK
artifact has L≠H (bracket-valued) and our fixpoint has a resolved single
value via median-pin.

### 4.3 `GLOBAL.C3` / E2 do not apply

The bracket apparatus is what the new rule deletes (`roadmap-2026-07-28.md`
§2). This experiment ships values, not brackets. EXP-2's A4 (ADR-0009
operator with median-pin post-processing) is the mechanism.

The operator is the same ADR-0009 operator used in EXP-4 (Black=max,

iterations but remain well within budget.

### Sweep log


H converges faster than L — the same asymmetry observed at 3×2

Black's forced-termination attractor (L, ascending from −9) grows slower
than White's (H, descending from +9), because the starting player's
advantage is reflected in L's slower convergence.

## 7. Cross-check (brute-force)

A full-history brute-force from the empty 3×3 goban is **not feasible** —
the game tree exceeds 10M nodes (EXP-4's 3×2 root budget-exhausted at 10M;
3×3 is strictly larger). This is stated explicitly rather than skipped.

From **late positions** (≤1 empty point, passes≥1, sampled from the dense
end of the linear index space), brute-force with 50M node budget per state:

| result | count |
|---|---|
| agreements | 50 |
| mismatches | 0 |
| budget-exhausted | 0 |
| sample size | 50 |

All 50 within-budget evaluations agree with the fixpoint. The 50 sampled
states are at passes=2 (terminal) or passes=1 with 1 empty point — the
closest to termination the reachable graph contains. This is a spot check,
not an exhaustive verification; the sample is necessarily biased toward
positions where the game tree is small enough for brute-force.

## 8. Calibration

### Known-good
2×2 root = 0, 3×2 root = 0, re-run from this binary. Both pass. The 2×2
five-anchor smoke test from EXP-4 is embedded (empty-B, empty-W, full-B,
passes=1, passes=2).

### Known-bad 1 (perturbation)
State lin=150 (a non-root state with L==H=9) was perturbed to L=H=10. The
symmetry checker found **2 inversion violations** — one from the perturbed
state itself (imbalanced with its colour inverse) and one from its inverse.
A root-only check would not have detected this perturbation (the root was
untouched). The checker can identify a perturbed state below the root.

### Known-bad 2 (PSK artifact)
Both the PSK 3×3 artifact (`artifacts/oracle-3x3.wzo`) and our fixpoint
return +9 at the empty-goban root. A root-only comparison would pass both
rules as "correct". The distinction: the PSK artifact has **8,698
ko-sensitive slots** where L≠H (bracket-valued, no resolved score), while
our fixpoint resolves every reachable state to a single value via
median-pin. The checker must be able to tell the two tables apart below
the root, or it cannot certify that we solved the new rule rather than the
old one. The structural argument (PSK: bracket-valued ko-sensitive region;
new rule: single-valued everywhere) is documented here; a byte-level
comparison against the artifact file is deferred to a separate tool due to
Zig 0.16 `fs` API migration.

## 9. What could not be established

- **Full-table brute-force verification.** The 3×3 game tree from the empty
  goban exceeds feasible budget. The 50-state late-position sample is a spot
  check only.
- **Byte-level PSK artifact comparison.** The artifact file format uses
  dense colex addressing with 6 columns; reading it correctly requires the
  exact column mapping (`docs/engine/ARCHITECTURE.md`), which is engine code
  and was not imported. The structural argument stands in lieu of a
  byte-level diff.
- **History-conditioned semantics.** PINRULE-SUFFICIENCY showed the
  median-pin rule is fresh-start-consistent at 3×2 but that history-
  conditioned arrivals can diverge. The 3×3 root value (+9, L==H) is
  consistent with both semantics (no divergence possible when L==H), but
  non-root states with L≠H may differ between fresh-start and history-
  conditioned evaluations. This is the same class of divergence at both
  3×2 and 3×3.
- **Whether the pin_T states (1,248) are genuine "neither player can force
  termination" or artefacts of the loopy-game semantics.** The median-pin
  rule resolves L<0<H to TIE by construction; whether all such states
  correspond to genuine long-cycle positions is not verified state-by-state.
