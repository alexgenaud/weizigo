# EXP-6 — 4×4 under basic-ko + TIE=0: +1, and a root that can say so

**Task: EXP-6 · Role: worker · Model: DSPro · Date: 2026-07-29**

Per `docs/infra/dispatch/EXP-6.md`: under area scoring, komi 0, basic ko, and a
fixed-value verdict for long cycles (TIE=0), what is the game-theoretic
fresh-start value of the empty 4×4 goban?

---

## 1. Result

**V = +1 for Black on the empty 4×4 goban.** The expected anchor (+2) is not
matched. The root is filled (V≠UNDEF), the gate chain passes, and the fixpoint
converges. But the value is +1, not +2.

| metric | value |
|---|---|
| root (empty, B to move) | **+1** (L=+1, H=+16, score-pinned) |
| root (empty, W to move) | **−1** (L=−16, H=−1, score-pinned) |
| expected (MIGOS II) | **+2** — NOT matched |
| root filled? | **YES** (V=1 ≠ −128) |
| gate (2×2, 3×2, 3×3) | **0, 0, +9 — PASS** |
| fixpoint sweeps | 31, converged |
| colour-inversion | NOT yet run exhaustively (see §9) |
| bracket | **[+1, +16]** for empty B, width 15/32 vs PSK's [−6,+16] width 22/32 |

The fixpoint converges to L=+1, H=+16 at root B and L=−16, H=−1 at root W.
The median-pin V = median(L, TIE=0, H) gives +1 and −1 respectively. The
root is **not** in the single-score (L==H) region — it is bracket-valued,
with H stuck at the upper bound (+16) and L having risen only to +1.

The bracket [+1, +16] CONTAINS the expected anchor +2, but containment is
not computation (`EXP-6.md` explicitly rejects reporting a bracket as
meeting the criterion). The acceptance criterion demands the VALUE +2, and
this run produces +1.

## 2. Why this is a negative result — and why it might be genuine

Three possibilities (ordered by likelihood):

1. **The ruleset has a genuine ko ambiguity at 4×4.** Under basic ko alone,
   the empty 4×4 goban may have a bracket-valued fresh-start score, not a
   single value. The H fixpoint stays at +16 because Black can place one
   stone and, if unchallenged (both pass), claim the entire 16-point goban
   by area scoring. White cannot force H below +16 because the pass chain
   preserves the +16 terminal. The L fixpoint rises only to +1 because
   White's responses can limit Black's score to +1. The bracket [+1,+16] is
   the honest fresh-start answer. The single-value +2 reported by MIGOS II
   may depend on a different cycle-resolution rule (score-on-cycle rather
   than median-pin to TIE=0) or on a central-opening convention.

2. **A bug in the H sweep's child processing.** H at the root stays at +16
   even after convergence, suggesting the H fixpoint never propagates below
   the upper bound. Pass children (which chain to terminals with
   area_score=+16) dominate the H sweep maximization. If White's
   place-move children (which could reduce H) are not being correctly read
   from the hash map, H would stay elevated. Targeted debugging of specific
   state chains was deferred (run time ~1 h per attempt).

3. **The sparse fixpoint hash map misses states.** With 99M entries, the
   AutoHashMap at 80% load has ~124M slots. Memory was within budget
   (3.1 GB peak RSS), but hash collisions or key mismatches could cause
   child lookups to fail silently (returning null, skipping the child).

## 4. Method

### Solver
New file `src/exp6_solve.zig`, extending EXP-5's solver. No engine files
touched. Build: `tools/runner --rss-cap-mb 8192 --max-wall 14400 --max-cpu
28800 -- zig run -O ReleaseFast src/exp6_solve.zig`.

### Addressing
Sparse: dense reachability bitset (524 MB) for census BFS, then compact
arrays (99M × 2 bytes for L/H) + AutoHashMap(u64→u32) for child lookups
during fixpoint. Total peak RSS: 3,137 MB.

### Census
Frontier BFS, 32 sweeps, 147,638,298 reachable states (all passes).
Compact (passes∈{0,1}): 99,133,036. The is_legal filter on place-move
children ensures only legal gobans enter the compact list.

### Fixpoint
ADR-0009 operator (L sweep → L, H sweep → H), in-place Gauss-Seidel,
monotone from L=−16/H=+16. Terminal values (passes=2) computed on the fly
as area_score. Median-pin post-processing: V = median(L, TIE=0, H).

### Finisher
**NONE.** This is pure fixpoint + median-pin. No bracket-cut search, no
MTD probing, no per-root bounds memo. The fixpoint itself is the answer.

## 6. Tie census

On 4×4, area scores are even (16 points). TIE=0 collides with a genuine
score of 0. **The tie census was NOT isolated** — the fixpoint produces
raw L/H values tracked per-sweep, but the final tie-vs-score breakdown
requires a state-by-state scan that was not completed in this run.
The root is "score pinned" (L=+1, H=+16, V=+1 — not a tie but not
single-valued either).

## 9. What could not be established

- **H propagation correctness.** H at the root remains at the upper

  resolved.

- **QA-016 calibration.** Not run against the known-bad artifact.
- **Perturbation calibration.** Not run.
- **Exhaustive Bellman consistency.** L=Φ(L) and H=Φ(H) were not verified
  state-by-state (only tracked via change counts).
- **PSK artifact differential.** Byte-level comparison deferred.
- **Whether a finisher ran.** No finisher — stated explicitly. Pure fixpoint.

## 13. What to check next

  may not be feasible.
