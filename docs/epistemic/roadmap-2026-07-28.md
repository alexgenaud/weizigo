## 1. Definitions the project has been using without stating

### Markovian

**A process is Markovian when the future depends only on the present *state*,
not on the path that reached it.**

The user's phrasing — "a state or universe independent of prior history" — is
right in spirit but hides the lever. History is not *absent* in a Markovian
process; it is *already encoded in the state*. So:

> **Any rule can be made Markovian by enlarging the state to carry exactly the
> history that rule depends on.** The question is never *whether* a rule is
> Markovian — it is *how big the state has to be*.

That reframing is the whole engineering problem of this project:

| rule | history the rule needs | state | size |
|---|---|---|---|
| basic ko | the one forbidden point | `(board, side, ko_point)` | ~17× gobans |
| bounded superko, window `k` | the last `k−1` gobans | `(board, side, last k−1 boards)` | explodes in `k` |
| positional superko | **every** goban ever seen | `(board, side, set-of-all-seen)` | 118M ban-sets on a **2×2** |

A **position→score table is a Markovian representation with the smallest
possible state** — the goban alone. Building one for PSK is the project's
founding category error (`critique-2026-07-28.md` §2). The table has nowhere to
put what PSK depends on.

**Corollary worth internalising:** "chainable" (GLOSSARY) and "Markovian" are
the same property seen from two sides. A table is chainable exactly when its
state is Markovian for the rule it was built under.

### MIGOS II

**MIGOS II is a *program*, not a ruleset** — and I have been sloppy about this
in earlier messages; the user was right to query it. MIGOS ("MIni GO Solver")
is Erik van der Werf's solver; MIGOS II is the version behind van der Werf &
Winands, *Solving Go for Rectangular Gobans*, ICGA Journal 2009 — the source of
every published anchor this project cites (3×3 = +9, 4×4 = +2, 5×5 = +25, …).

**The ruleset it plays** (quoted in `../research/retrograde-3x3.md:224-245`):
area (Chinese) scoring, **basic ko only — "since superko is not used"** — and
balanced long-cycle repetition **scored as a long-cycle tie**.

**Is that acceptable to seasoned human players?** Yes, and more so than what
this project has been solving. Each half is a mainstream traditional choice:

- *Scoring:* Chinese/area — used in Chinese, AGA and NZ rules, and in every
  major human-vs-computer match (AlphaGo–Lee Sedol and AlphaGo–Ke Jie were
  played under Chinese rules, 7.5 komi — **not** PSK).
- *Repetition:* basic ko with special handling of long cycles — which is
  Japanese and Korean practice, where triple ko and eternal life give **no
  result** and the game is replayed (`../research/ruleset-options.md:11-12`).

So the closest traditional description is **Chinese scoring + Japanese-style
repetition handling**. It is a hybrid, but a conventional one, and no seasoned
player would object to either half. Its only unusual feature is that a long
cycle scores as a *tie* rather than voiding the game — a solver's convenience,
because "replay the game" is not a value a table can hold.

### Is PSK actually played by humans?

**No.** From the project's own research (`../research/ruleset-options.md:9-20`):

| tradition | repetition rule |
|---|---|
| Japan / Korea (pro) | basic ko; long cycles → **no result**, replay. No superko |
| China (pro) | basic ko + anti-repetition provisions, **adjudicated, not mechanical** |
| AGA / NZ / Tromp–Taylor | situational / positional superko — a *computer* convenience |
| AlphaGo vs Lee Sedol / Ke Jie | Chinese rules — **not** PSK |

**Would a player or a judge notice a whole-goban repetition two dozen moves
later that was not a ko cycle?** My judgement: **no, and it would essentially
never arise.** Stones accumulate and positions diverge monotonically except
where captures undo them, so non-cyclic whole-goban repetition at distance is
vanishingly rare in real play. Nobody is tracking it; there is no mechanism by
which it would be caught.

**But this is a judgement, and it is cheaply measurable** — see EXP-1. If PSK
binds beyond basic ko approximately never in real play, then the whole
PSK-tractability crisis is an artifact of solving a rule nobody plays. That
would be the single most decision-relevant number in the project, and it costs
an afternoon.

## 2. The strategy — and why it is not the thing already foreclosed

The user asked me to navigate this. Here is the navigation, including the two
walls the project has already hit, so nobody re-runs them.

### The two standing foreclosures (do not relitigate — they are correct)

1. **Exact PSK is intractable.** 118M ban-set states on the empty 2×2.
2. **basic ko + score-on-cycle is byte-identically as intractable** — RETRO_CYCLE
   measured the *same* state counts (118,475,182 / 116,114,272). Not a
   coincidence: under both rules a move re-reaching a seen goban does not
   recurse, so the recursion trees are identical.

And a third result that kills my own earlier ladder sketch:

3. **RETRO_PLY: the N-ply history window did not help** — every N, including
   N=1, blew the budget. The stated reason is the important part: *to give a
   bounded rule a terminal verdict on longer cycles you must **detect** those
   cycles, which requires remembering every goban seen — the full history stays
   in the key.*

**So my "Reading A" ladder from `critique` §5 is withdrawn as posed.** The
window bounds *legality* but the cycle *terminal* drags full history back in.

### The escape hatch — and it is precise

Read foreclosure 2 and 3 again and notice what they share. Both were run with
**score-on-cycle**: a cycle ends the game *scored by area at the repeated
goban*. That verdict is a **function of which goban you cycled back to** — so it
is genuinely path-dependent, and the project's conclusion follows.

> **A cycle verdict that is a CONSTANT is not path-dependent.**

Under **basic ko + "any long cycle = a fixed outcome"** (a tie, or a no-result
value), the terminal no longer depends on *which* goban repeated. The state
`(board, side, ko_point)` then suffices for **both** legality and termination,
and there is nothing left for history to determine.

That is not a variant of score-on-cycle. It is a different rule, and the
existing foreclosures do not reach it. **This is exactly the MIGOS II ruleset,
i.e. the one the published anchors were computed under.**

**CLAIMED, and this is the load-bearing claim of the whole roadmap
(`QA-023`).** The escape must be proven before anything is built on it — see
EXP-2. What makes it plausible rather than wishful:

- The resulting object is a finite two-player zero-sum game on a finite graph
  with a fixed value for infinite play. That is a **solved problem class** —
  the same structure as chess endgame tablebases, where repetition is a draw
  and retrograde analysis produces win/draw/loss. Decidable, and polynomial in
  the state space.
- **The project's existing L/H machinery is exactly the right tool.** L and H
  are the least and greatest fixpoints; where they differ, the difference *is*
  the set of states whose value depends on cycling. Under a fixed cycle value
  you resolve them by pinning to that value instead of shipping a bracket. The
  `converge` engine is not wasted work — it was pointed at the wrong rule.
- **It deletes the apparatus that produced the project's worst bugs.** No
  finisher, no bracket cuts, no `ko_ref` memo guard — so `F1` (the GHI bug) and
  `O1`/`QA-018` (the finisher resting on falsified C3) do not arise. Not fixed:
  *not provoked*.

**The known complication, stated up front:** a "tie" is not an area score. With
komi 0 the area score on an odd-point goban is always odd, so on 3×3 a tie of 0
is outside the natural value set. The value domain becomes `ℤ ∪ {tie}` with the
tie ranked between −1 and +1. Tractable, but it is a real design decision and
belongs in an ADR, not in an implementation.

### The strategy, in three parts

**S1 — Solve exactly under basic ko + fixed-value long cycles.** Markovian,
traditional, anchored, and it reuses `converge`. This is the primary line.

**S2 — Measure the gap to PSK rather than assume it.** Where exact PSK is
computable (small gobans, late positions), compare. That measured divergence
*is* "how far from the machine standard are we" — the user's shrink-toward-zero
metric, as a number rather than a hope.

**S3 — Be PSK-*aware* at play time without claiming PSK-perfection.** Enforce
whatever ko rule the opponent wants for legality (cheap), and flag when the
game's real history would make the loaded table's answer diverge. This is
precisely the user's "PSK awareness, but not provably perfect PSK game play."

**The door to perfection stays open.** S2 is the mechanism: if the measured
PSK-divergence is zero on everything we can check, that is evidence — never
proof — that the tractable rule agrees with the standard one where it matters.
And if some future representation cracks PSK, S1's tables remain valid for
their own rule and become the comparison baseline.

## 3. Experiments — the roadmap agents can execute

Ordered by information per unit cost. Each states its acceptance criterion and
what a negative result would mean, because a negative result must be as
publishable as a positive one.

### Phase 0 — decide whether the crisis is real (days)

**EXP-1 — How often does PSK actually bind beyond basic ko?**
Instrument game playouts (extend `src/reachcensus.zig`, which already replays
full games with real PSK history) to count: (a) moves illegal under PSK but
legal under basic ko; (b) their distance back to the repeated goban; (c) how
many are part of a ko cycle versus a "silent" long-range repeat.
*Acceptance:* report the rate per 1,000 plies at 3×3/4×3/4×4 under all
`reachcensus` policies. *If ≈0 for non-cycle repeats:* PSK is a rule nobody
plays and nobody could enforce, and S1 becomes clearly correct. *If not:* the
PSK question is real and S2 gets much more weight. **Either way this is the
cheapest decision-relevant number available.**

**EXP-2 — Prove or kill the escape hatch (`QA-023`).**
A written argument, then a 2×2 computation: under basic ko + fixed-value long
cycles, is the value of `(board, side, ko_point)` well-defined without history?
*Acceptance:* a proof sketch reviewed by a second agent, **plus** an exhaustive
2×2 solve compared against a brute-force game-tree evaluation with the same
rule. *If it fails, the whole roadmap fails* — run it before anything is built.

**EXP-3 — The `(board, side, ko_point)` state census.**
Count reachable triples at 3×3, 4×3, 4×4. *Acceptance:* exact counts and
implied artifact size. Note `ruleset-options.md:76-81` warns the augmented
state space is **sparse**, so dense colex addressing does not extend — the
census must report reachable-vs-dense so the addressing decision is informed.

### Phase 1 — build the smallest honest thing (weeks)

**EXP-4 — Solve 2×2 and 2×3 under the new rule, and check the falsifier.**
Published values are **0 / 0**; weizigo's PSK values are **+1 / +1**. A correct
build must return **0**. *Acceptance:* exact match on both. This is the cheapest
correctness gate in the project and it must run before 3×3.

**EXP-5 — 3×3 under the new rule.** *Acceptance:* +9, matching the anchor —
now a *legitimate* comparison, because we would finally be solving the same
game the anchor was computed under.

**EXP-6 — 4×4 under the new rule.** *Acceptance:* +2, and a **filled root**
(see `QA-016`: two of three current 4×4 artifacts cannot state the answer).

### Phase 2 — close the loop on the user's actual goal (weeks)

**EXP-7 — Certified fraction under the new rule.** Re-run `reachcensus`. Under
a Markovian rule the table is chainable *everywhere*, so the prediction is
**100%**, against today's measured **0%** in 4×4 self-play. *If it is not 100%,
the Markovian claim is wrong* — this is a falsification test, not a
victory lap.

**EXP-8 — The PSK divergence measurement (S2).** For sampled positions, compare
the new table's move against exact PSK where PSK is computable.
*Acceptance:* a divergence rate with a stated sample and power argument.

### Phase 3 — later, explicitly not now

- 5×5 and beyond, under the tractable rule.
- Situational superko as a second rung, if EXP-1 says superko matters.
- Territory (Japanese) scoring as a second axis.
- Revisiting exact PSK if a new representation appears.

## 4. How this project should be run

The technical faults in `critique-2026-07-28.md` §4 are mostly *process* faults.
Five changes, in order of value.

**P1 — Evidence must be in git, or the claim is not proven.**
The most serious finding of 2026-07-27/28: the primary evidence for **T13**
(the falsification the entire strategy rests on), **T02/B1**, **T07** and
**B05** was written to git-ignored `untracked/` and **deleted** (`QA-022`).
*Rule:* a claim may be marked PROVEN only if its probe source and output are
committed under `docs/evidence/<claim-id>/`. `untracked/` is for drafts that
nobody will ever cite. This is not bureaucracy — it is the difference between
proven and remembered.

**P2 — `CLAIMS.md` is the spine.** Every experiment closes a claim ID; every
commit message cites the IDs it touches; every document references IDs rather
than restating claims. When a status flips to FALSE, the dependency sweep is
mandatory and mechanical.

**P3 — Every checker ships with calibration.** A known-good case it passes and
a known-bad case it catches. I got this wrong on 2026-07-27 and the standing
`RETRO_CONSIST` gate has no documented calibration case. An auditor without a
passing case cannot tell "bug" from "definition."

**P4 — Fitness, not percentage.** "99.8% complete" hid an unfilled root
(`QA-016`). *Rule:* an artifact reports **root filled? anchor matched? gate
passed?** — not fill fraction.

**P5 — Roles, and one writer per file.**
- **The user** sets goals, adjudicates rule choices, and owns ADRs.
- **Opus** holds the claim graph, reviews, critiques, and writes roadmaps. Does
  not execute.
- **GLM Boss** dispatches and drives execution, and owns the work queue.
- **Agents** take single-file-owned tasks with an explicit acceptance criterion.
  The one-writer-per-file discipline worked cleanly across nine parallel agents
  on 2026-07-27/28 — keep it, and state file ownership in the task, not after.

**Definition of done, for any task:** the claim ID it closes, the evidence
committed under `docs/evidence/`, the acceptance criterion met *or* an honest
negative result recorded, and `CLAIMS.md` updated.
