## What I was asked

Run I2 — `V(-pos,-side) == -V(pos,side)`, for bound tables `L(pos,side) ==
-H(inverted)` and `H(pos,side) == -L(inverted)` where inverted =
`(colour_flip(colex), 1-side, ko, passes)` — against the 4×4 WZO2 artifact
(`untracked/oracle-v2/oracle-4x4-v2.wzo2`, SHA-256 `0c3366f0…`) and the 3×3
WZO2, under `tools/runner`, with an independent re-implementation (R8),
reporting violations with witnesses and the denominator.

## Result — I2 PASS on both artifacts

| artifact | checked (denominator) | violations | not_found | verdict |
|---|---|---|---|---|
| `oracle-4x4-v2.wzo2` (`0c3366f0…`) | 99,133,036 | **0** | 0 | **PASS** |
| `oracle-3x3-v2.wzo2` (`d79c17cd…`) | 49,428 | **0** | 0 | **PASS** |

`not_found` counts stored entries whose inverted key is absent from the
artifact (missing inverted group, or no entry with the matching masked key in
the inverted group) — a completeness-adjacent failure, counted separately from
the value mismatch `violations`, exactly as T212's A3 checker did. Both are
zero. There are no witnesses to report: the invariant holds on every checked
entry.

## Instrument independence and calibration

The checker was written from the format spec
(`docs/epic-01-markovian/sprints/oracle-v2/pass0/design-M1.md`) and the
invariant definition (DIRECTION §7.1/A3), importing nothing from `src/`
(stdlib + numpy only). It contains **two independent implementations** of the
check itself:

- `run_i2_reference` — pure-Python per-group dict pairing, the direct analogue
  of T212's `checkA3` loop (same masked-key lookup convention: terminal bit
  cleared, first match wins).
- `run_i2_numpy` — vectorised composite-key check: global key
  `(colex << 8) | (kb & 0xFE)`, inverted key `(flip(colex) << 8) | (mkb ^ 0x02)`
  (bit 1 = side, terminal masked), `searchsorted(side='left')` for first-match
  semantics, chunked over groups to bound memory.

Agreement checks:

| run | ref | numpy | agreement |
|---|---|---|---|
| 3×3 full artifact | 0 viol / 0 nf / 49,428 checked | 0 / 0 / 49,428 | **yes** |
| 4×4 head 2M groups (colex-low window) | 0 viol / 58 nf / 7,939,236 checked | 0 / 58 / 7,939,236 | **yes** |
| 4×4 full artifact | (too slow, pure Python) | 0 / 0 / 99,133,036 | — |

The 58 not_found in the 2M-group window are a window-boundary artifact of the
limited run (entries whose inverted group lies beyond the sampled head), not a
defect: the full-artifact run shows not_found = 0, and both implementations
agree on the window. The 2M-group window was chosen deliberately because the
v1 defect (T260) clustered at low colex indices (few stones).

The colex layer math was verified independently before any artifact was read
(`--verify-math`): exhaustive encode/decode/flip round-trip on all 19,683 3×3
indices, plus 199,548 sampled 4×4 indices (flip is an involution; flip(x) ==
encode(colour-swap(decode(x)))).

Calibration (`--calibrate`, synthetic 2×2 fixtures exercising the same I2
path):

| fixture | expected | result |
|---|---|---|
| known-good | PASS, 0 violations | PASS, 0 viol, 0 nf |
| known-bad (one L perturbed +1) | FAIL, ≥1 violation | FAIL, 4 viol (both directions of the perturbed pair) |
| known-bad-missing (a group dropped) | FAIL, ≥1 not_found | FAIL, 0 viol, 4 nf |

All three fixtures pass both implementations with agreement. The instrument
demonstrably detects both failure modes it is designed to detect.

## What this means — and a stale premise in the brief

**The brief's premise "I2 has never been run against WZO2" is stale.** The
register records T212's M4a A3 run (2026-08-01) on this exact 4×4 artifact:
`checked=99133036 violations=0 not_found=0`, verdict PASS
(`docs/evidence/ORACLE-V2/m4a-accept-T212-2026-08-01.md`). I2 *is* A3
(DIRECTION §7.1: "A3 (colour inversion, exhaustive) … = I2"). The T258 fleet
run tested only the WZO1 list; the M4a acceptance instrument had already run
this invariant on WZO2.

The independent re-derivation is still the right Phase-1 move: the register is
presumed unverified until re-derived end-to-end, and T212's checker lived in
`src/` (same codebase as the builder — the exact coupling R8 exists to break).
**This run re-derives the registered claim with a fully independent
instrument, and confirms it: 0 violations / 99,133,036 checked.**

**Calibration reading.** The 4×4 WZO2 is a certified-defective calibration
input (CODE.WZO2-INCOMPLETE was CLAIMED with ~6.77M missing passes=1 side-entries
at the time of this run; since refuted — the true figure is 131,068 provably
unreachable entries, `CODE.WZO2-PASS1-LAW:PROVEN` per T266/T277/T279). I2 sees a
clean inversion on it. The two defects are orthogonal: the incompleteness is
colour-symmetric in its absence (missing entries come in flip-pairs, so every
*present* entry's inverse is present), and I2 only tests present entries. A
battery that expects I2 to fail this artifact is wrong; the invariant that
catches the incompleteness is A1/A2/A8 (completeness-family), not I2. This is
exactly the kind of reading Phase 1 wants: **I2 is not sensitive to the WZO2
defect class, and the WZO2 artifact does not share the v1 basic-ko inversion
defect** (`4x4.V1-INVSYM-BROKEN`, 11,658,047 violations ≈ 48% — not present
here).
