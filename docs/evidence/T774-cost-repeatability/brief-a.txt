# Read-only audit — silent-wrong-answer hazards in the cost-measurement surface

You are auditing this repository's per-run cost-measurement instruments. **This task is strictly read-only.** Run no test script, edit no file, commit nothing, create no files other than your report on stdout. Reading files and running non-mutating shell inspection (`grep`, `sed -n`, `ls`, `cat`, `wc`, `git show`) is expected.

## Background (all of it true, none of it the answer)

This project records, per model run, total tokens (input+cache+output), cpu-seconds, and peak rss. Three instruments carry the readings, and the project has a standing rule: **a silent wrong answer outranks a loud crash** — a tool that reports success while recording nothing, or records the wrong run's numbers, is the defect class that has actually bitten this project (a budget script that looped forever under ReleaseFast; a parser that read a 221-line register as empty and reported "nothing to absorb"; a metrics ledger whose own reason for UNKNOWN readings was false). Your job is to find the next instances in THIS surface before they bite.

The three instruments:

1. `tools/token-capture.py` — `read_pi_session(path)` sums `usage` objects from one pi session JSONL (assistant turns plus summary/compaction entries) into {input, output, cache_read, cache_write, reasoning, total}; `parse_claude_envelope(raw)` extracts usage from `claude -p --output-format json` stdout.
2. `tools/runner` — measures wall, cpu-seconds (ps cumulative time) and peak rss_mb for the wrapped command; at close, captures tokens via token-capture (claude envelope parse for claude lanes, `read_pi_session` for pi/ollama lanes with `--session <path>`); writes run records to `untracked/runs/<task>.json` (attempt-archived to `<task>.<N>.json`) and appends heartbeats to `untracked/heartbeat.jsonl`.
3. `tools/token-backfill.py` — retroactive scan of `~/.pi/agent/sessions/<cwd-slug>/` session files and appends to the tokens ledger.

## What to look for

Any path by which these instruments can produce a **wrong or silently-empty reading** on a completed run:
- a completed run whose tokens end up recorded as 0 instead of UNKNOWN (a silent zero is a free lane in any cost comparison);
- a session file attributed to the wrong lane (concurrent runs sharing a session dir);
- a usage record double-counted or skipped in the sums (turn vs summary vs compaction; the `total` key; `totalTokens` vs the component keys);
- a claude envelope parsed with a missing key defaulting to 0;
- a run record that is torn, missing its finalize, or reads as success without exit/end — or an attempt archive that loses or mislabels an attempt;
- a cpu or rss reading that is measured on the wrong process or the wrong process group.

Consider at least: unreadable/absent session files (each must be UNKNOWN with a reason, never 0); empty usage objects; `errors="replace"` on a session file; JSON lines that fail to parse inside `read_pi_session` (counted as `bad`, silently skipped); claude envelopes with `is_error=true`; envelopes whose `result` is missing; `--session` paths that never get written; the `total` derived vs provider-reported mismatch; and the runner's degraded (no-identity) mode.
