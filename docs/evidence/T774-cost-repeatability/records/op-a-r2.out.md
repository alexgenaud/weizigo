## 3. Checked and found SAFE

Each of these looks like the defect class but is not.

1. **`errors="replace"` on session files** — `token-capture.py:357`, `:491`. A careless reader flags mojibake corrupting sums. It cannot: replacement characters only appear inside decoded text, and the only values ever summed are fetched by key and gated on `isinstance(v, (int, float))` (`_add_usage:308`). A mangled line either still parses (numbers unaffected) or fails `json.loads` and is skipped. The defect here is that the skip is uncounted (#12/#13), not that the numbers are corrupted.
2. **`is_error=true` envelope with usage present** — `runner:2223–2225`: `out["missing_reason"] = ("claude api error (is_error=true, zero usage)")`. This is explicitly MISSING, never a 0/0 reading, and it is covered by a control: `tools/regression-token-capture.sh:160–166` asserts `meta3["is_error"] and usage3 is not None`.
3. **Envelope with a missing `result` key** — `token-capture.py:266–267`: `result = obj.get("result"); if not isinstance(result, str): result = text`. Passthrough of the raw output, not silence, and it is orthogonal to the reading: usage is read from `obj.get("usage")` at `:268`, so a missing `result` cannot zero the counts.
4. **`--session` given an id instead of a path, or `--session=path`** — `_argv_session_path:1596–1602` matches only the flag pair, and a non-file resolves to `{"ok": False, "reason": "session file missing: …"}` (`token-capture.py:352`) which `runner:2270` turns into UNKNOWN with the reason. Both degrade loudly; neither becomes 0.
5. **Relative `--session` path resolved against the *runner's* cwd** — `runner:2256–2257`: `os.path.join(os.getcwd(), session_path)`. Correct, not a bug: `subprocess.Popen(argv, preexec_fn=…)` at `:2766` passes no `cwd=`, so the child inherits the runner's cwd and the two resolutions are the same directory.
6. **Torn run records** — `_write_run_record:526–551` writes `path + ".tmp"` then `os.replace`. For a single writer the visible file is always old-complete or new-complete, and the launch record is written before the monitor loop so a SIGKILL of the runner still leaves evidence. (The *concurrent* same-identity case shares one `.tmp` name — that is #18, a different claim.)
7. **Attempt archives double-counted by the p95 census** — `recompute_harness_p95:1948` iterates every `*.json` in `untracked/runs/`, which includes `<task>.<N>.json`. Not a double count: `_begin_attempt:515` uses `os.replace` (a move, not a copy), so each physical attempt exists at exactly one path, and the docstring at `:511–513` states this is deliberate.
8. **The 2-second `_drain_stdout` deadline truncating the claude envelope** — looks like the envelope's only capture is a 2 s window. It is not: stdout is drained continuously inside the monitor loop (`runner:2891–2894`, `chunk = proc.stdout.read()` under `select`), so the post-exit drain (`:2882`) is a top-up and the child can never block on a full pipe. Truncation would require 2 s of *continuously available* data after exit.
9. **Summary/compaction usage double-counting the assistant turns** — `token-capture.py:379–384`. The `if`/`elif` branches are mutually exclusive on `o["type"]`, so a `summary` entry's usage is added once and never alongside a `message`. (That these entries do *not* increment `turns` is the separate matter in #1.)
10. **`total` / `totalTokens` corrupting the cost fields** — the derived-vs-provider mismatch is real (`_harness_key:311–329` maps `total → totalTokens`, while `parse_claude_envelope:265` computes `total = input+output+cache_read+cache_write`), but no cost field is derived from it: `tokens_in`/`tokens_out` come from components everywhere (`token-capture.py:537–538`, `runner:2217–2220`, `:2262–2266`). The mismatch can only surface in the human report's `total` column, which is #11.
11. **`_load_token_capture` returning None** — `runner:1540–1559` never raises, and every branch of the `tc is None` path sets an explicit `missing_reason` and `session_reason` (`:2299–2311`). Absence of the instrument is UNKNOWN with a reason, not 0. Same for a half-updated pair: `getattr(tc, "read_pi_session", None) is None` → explicit reason (`:2249–2253`).
12. **`canon_tag` and the `stealth/ox-alpha` serving tag** — `token-capture.py:126–133` strips `:cloud`, maps `kimi-k2.7-code` and `stealth/ox-alpha`; it is applied on every write and read path (`runner:2331`, `merge_models:670`, `backfill:172`) and it has both a parity control (`tools/regression-token-capture-canon.sh`, named at `:124`) and a seeded-defect control inside backfill (`:249–254`).
13. **`token-backfill --validate` with nothing to compare** — `:305–308` prints "the method is UNVALIDATED, not validated" and returns False (exit 1). The honest direction: no comparable lane is not reported as agreement.
14. **`deepseek_rate_band` on an unparseable timestamp** — `:409–421` returns None rather than guessing a band, and `runner:2321–2330` records a reason naming the family's pricing unit for non-deepseek lanes. A band is never invented.
15. **`_json_output_lane` requiring the exact pair `--output-format json`** — `runner:1567–1574`. A `stream-json` or `--output-format=json` lane is misdetected, but it degrades to the pi branch → no `--session` → UNKNOWN with a long explicit reason (`:2279–2287`). Wrong path, safe direction. (The `stream-json` JSONL branch in `parse_claude_envelope:239–246` is consequently unreachable from the runner at HEAD — dead defensive code, not a hazard.)
