## 3. Checked and found SAFE

- **`token-capture.py:350‑351` — absent session file.** `if not os.path.isfile(path): return {"ok": False, "reason": "session file missing: %s" % path}` — UNKNOWN with the *path*, never 0. `runner:2270‑2273` wraps it into `missing_reason` + `session_reason`. A `--session` path that never gets written is correctly a missing-with-reason.
- **`token-capture.py:357` — `errors="replace"`.** `fh = open(path, errors="replace")` cannot silently alter a *number*: an invalid byte inside a numeric token becomes U+FFFD, which makes the whole line unparseable, so the line is dropped by the `except ValueError` rather than mis-summed. Its only real cost is the dropped-line count, which is site 8 — the decode mode itself is not the defect.
- **`runner:2212` / `2222‑2225` — `is_error` envelopes.** `if usage is not None and not meta.get("is_error"):` … `elif meta.get("is_error"): … "claude api error (is_error=true, zero usage)"`. An error envelope carrying `0/0` usage is recorded MISSING, exactly as the brief's hazard requires. The fixture at `tools/regression-token-capture.sh:106‑119` is the seeded control for it. Not a 0-reading path.
- **`token-capture.py:280‑285` — `output_tokens_details` defaulting reasoning to 0.** `otd = usage_obj.get("output_tokens_details")` … `if isinstance(t, (int, float)): thinking = t`. A careless reader flags this as a missing-key-becomes-0. It is safe: `reasoning` is not part of `tokens_in`/`tokens_out` (`runner:2217‑2220`), and its genuine value for a non-reasoning model *is* 0. Unlike site 5, a wrong 0 here cannot make a lane free.
- **`runner:526‑549` — run-record writes.** `with open(tmp,"w") … os.replace(tmp, path)`, same directory, plus `except OSError` unlinking the tmp. A reader sees either the previous complete record or the new complete one; a **torn** run record is not reachable through this function. (What *is* reachable is losing a whole record to a competing attempt — site 7 — which is a different mechanism.)
- **`runner:2352‑2357` — components on an `is_error` row.** The ledger row for an error envelope carries `input`/`output`/… while `tokens_in/out` are null. This looks like a leak of zeros into aggregates, but both readers gate the component sum on the reading test first (`token-capture.py:672` `if _ledger_reading(e):`; `:749‑750` `if not _ledger_reading(e): continue`), so those components are never aggregated. Safe as written.
- **`token-capture.py:461‑467` — task extraction.** `re.search(r"untracked/T(\d+)", text)` then `r"claim\s+T(\d+)"`, with the docstring's rule that "A bare `T<id>` mention is NOT matched". Prose citing another task cannot pull that task's session into a total. (The over-matching that *is* real — several sessions legitimately naming the same bundle — is site 10, not this regex.)
- **`token-capture.py:301‑309` — `_add_usage` on a malformed usage object.** `if not isinstance(usage, dict): return`, then `if isinstance(v, (int,float))`. A `usage: null` turn, or a string-valued count, adds nothing and cannot crash the scan or inject a bogus number.
- **`runner:2244` / `2278‑2291` — pi lane with no `--session`.** The no-path branch records an explicit UNKNOWN with a long reason and never a 0 or a directory-wide total, which is the correct answer to the concurrent-shared-session-dir problem. (The *text* of that reason is separately known-false for a wrong-lane reason — `token-backfill.py:7` — and site 14 is the claude-lane case; the numeric behaviour here is right.)
- **`runner:1458‑1486` — the drain deadline.** A 2 s bound on post-exit reads can truncate a claude envelope, but truncation makes every candidate unparseable, so `parse_claude_envelope` returns `usage=None` (`token-capture.py:253‑254`, `:269‑270`) and the run is MISSING-with-reason. Truncation cannot produce a *smaller wrong number* for `--output-format json`, because a single-object envelope has no earlier parseable usage record to fall back to.
- **`token-backfill.py:384‑387` — default dry run.** `if not args.commit: print("dry run — nothing written.")`. The recovery tool cannot append by accident.
- **`runner:480‑494` — `_begin_attempt` in degraded mode.** Returns `1` when `repo_root` is falsy; harmless, because `_write_run_record`/`_finalize_run_record` both early-return on the same falsy root (`:534`, and `record_root = None` at `:2693`), so no record is written under a wrong attempt number.
- **`token-backfill.py:139‑140` — CONFLICT rows.** `if rm and rm != entry["model"]: return "CONFLICT"` and `continue  # a conflicting attribution is never appended` (`:230`). A session whose model disagrees with the run record is dropped, not guessed — the wrong-lane attribution guard works on the axis it covers.
