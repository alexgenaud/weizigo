## 3. Checked and found SAFE

1. **`_add_usage` summing per-turn `totalTokens` is not cumulative double-counting** — `tools/token-capture.py:319` `"total": "totalTokens"`. The obvious fear is that pi's `totalTokens` is a running session total, making the sum quadratic. Measured on disk: `{"input":9697,"output":14,"cacheRead":0,"cacheWrite":0,"totalTokens":9711}` — 9697+14 = 9711, and the next turn's 10479+43+704 = 11226. Each turn's `totalTokens` is that turn's own sum. Summing is correct.
2. **`errors="replace"` cannot silently corrupt a count** — `:357`, `:491`. A replacement character either breaks the line's JSON (caught at :366, counted `bad`) or lands inside a string value; it cannot mutate an integer token field into a different integer. The real defect is the *uncounted skip* (row 12), not the decode mode.
3. **`parse_claude_envelope`'s "keep the LAST parseable object"** — `:243-252`. This cannot pick a mid-stream object out of a single-object envelope, because the whole-output/stripped/last-line parse at :235-242 succeeds first and `break`s. For genuine stream-json the last object *is* the `result` event. Correct as written.
4. **`session_id_present` type-guarding** — `:262-263` `isinstance(obj.get("session_id"), str)`. A non-string handle degrades to `null` plus a reason (`tools/runner:2210-2211`), never to a blank and never to an invented id. This is the discipline the token fields are missing.
5. **`_write_run_record`'s tmp + `os.replace`** — `:537-543`. Genuinely atomic; a reader sees the old complete record or the new one, never a torn one. The `.tmp` also cannot pollute readers: `recompute_harness_p95` filters `fn.endswith(".json")` (:1951), and `token-backfill.load_run_records` would fail its `json.load` and `continue` (:108-109).
6. **`--session <id>` given where a path was expected** — `:350-351` `if not os.path.isfile(path): return {"ok": False, "reason": "session file missing: %s"}`. Fails to UNKNOWN with the path named. Correct direction; the docstring at `tools/runner:1595` explicitly allows the id form.
7. **The `--session` relative-path resolution is not a cwd race** — `tools/runner:2245-2246` and `:2753-2754` use the identical `os.path.join(os.getcwd(), …)` expression at close and at launch, `subprocess.Popen` passes no `cwd=` (:2766) so the child inherits the runner's directory, and none of the three files calls `os.chdir` (verified by grep). Launch-time `mkdir` and close-time read hit the same file.
8. **Degraded (no-identity) mode does not fabricate a reading** — `:2693` `record_root = repo_root if not identity_degraded else None`; `_write_run_record` (:534) and `append_ledger` (:198) both early-return on a falsy root. A degraded run produces *absence*, never a `runner/<pid>`-keyed record that a reader could mistake for a lane. The envelope parse still runs (:2192, :3287), so the lane's text is not lost — the exact split the docstring at :2152-2155 claims.
9. **`_emit_heartbeat`'s `-1` → `None` → stripped key** — `:652-660`. A heartbeat with an unmeasured cpu *omits* the field rather than writing 0, which matches the project's "absence of an assertion is UNKNOWN" doctrine. Cited here because it is the correct pattern the same function receives `0.0` through on the normal exit path (row 4) — the sentinel convention exists and works; only the caller is wrong.
10. **`recompute_harness_p95`'s exclusions are sound** — `:1964-1979`. Killed attempts (`killed` / `signal` / `killed_by`) are excluded before anything else, records without `exit` are `incomplete`, and a completed record with `wall: null` is *also* pushed to `incomplete` rather than defaulting to 0. No censored or unmeasured attempt reaches a percentile. `_record_is_killed` (:1851-1852) correctly treats a `killed_by` of `None`/`"none"`/`""` as not-killed, and `_killed_by` never returns `None` for a non-empty reason (:446 falls back to `"harness-error"`).
11. **`_begin_attempt`'s numbering arithmetic** — `:511-523`. "From the existing count" is right for the ordinary sequence: 1st dispatch writes bare only; 2nd archives it as `.1` and returns 2; 3rd archives as `.2` and returns 3. The hazard is the swallowed rename failure (row 5) and the filename-collision series (row 19), not the counting.
12. **`deepseek_rate_band` refuses to guess** — `:419-421` returns `None` on an unparseable timestamp, and `tools/runner:2310-2330` records a band *or* a reason naming the family's pricing unit for every other family. No invented band.
13. **`plan()`'s "already has a reading → skip"** — `tools/token-backfill.py:165`. Retroactive scan genuinely never competes with dispatch-time truth at task level, and `control()` (:240-271) really exercises it against a live ledger entry rather than a fixture. The gap is that it is *task*-keyed, so an attempt-level miss inside a multi-attempt task is invisible — worth knowing, but the guard itself does what it says.
14. **`corroborate`'s `CONFLICT` grade is enforced, not decorative** — `:228-230` `continue` drops a conflicting row before `kept.append`, so a model disagreement is never appended. The defect is the *empty*-model escape (row 8), not the conflict handling.
