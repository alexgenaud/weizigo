# T372 — Z-R-TIE: Markovian state-sufficiency under *contrasting* histories

Task: T372 · Role: worker · Model: deepseek-v4-flash · identifier: flash/T372
Date: 2026-08-05 · Set K · Acceptance: this file (`test -s`)
Commit: instrument `src/t372_zrtie.zig` at HEAD `657f800`; stamp
`weizigo-t372-zrtie 657f800 zig 0.16.0` (built 2026-08-05, ReleaseSafe).

Re-derivation **#1 of the three** T354's register triage picked by walking the
requirement tree down from theorem Z (`docs/epistemic/register-triage-2026-08-04.md`
§5.1): the **Z-R-TIE** node (`docs/epic-01-markovian/AXIOMS.md` §3.2). The claim
under test is QA-023 C1 / `GLOBAL.H1-MARKOV` — that the `(position, side, passes,
ko)` tuple determines the value, so history beyond the ko field cannot matter.
The probe that was supposed to test this had never run with *contrasting*
histories: the 2B-3-AUDIT measured the history generator missing the shortest
arrival in **93% of states** with **~62% shared prefixes** — a sufficiency test
whose two "different" histories are nearly the same history cannot fail.

This task builds the missing instrument — a contrast-rich, shortest-arrival-first
history generator — runs the C1 probe on the corrected kernel at 3×2 (the rung
with the hand-verified witness), extends to 3×3, and runs the mandated controls
before the reading counts.

## 1. What the instrument is

`src/t372_zrtie.zig` — one new standalone-compiled instrument, additive-only per
the brief (no `build.zig` edit, no edits to engine sources or `src/vb_*.zig`;
T363/T369 hold the build graph; this file compiles with
`zig build-exe -O ReleaseSafe src/t372_zrtie.zig`). It is a **fresh,
self-contained re-implementation** (imports only `std` and `util.zig` for the
stdout/stderr discipline), generic over goban size (3×2 and 3×3):

- **Rules** — basic ko with the post-`2B-FIX-KO` lone-stone capture conjunct
  (proof-v2 §1.1 formalization (i)), Tromp-Taylor area scoring, single true game
  root (F1-CENSUS-GAP's `new+1` configuration). Written from the formalization,
  validated against the hand-verified witness (below).
- **Corrected L/H fixpoint** — monotone Gauss-Seidel (Black max / White min in
  both L and H; L ascends from −n, H descends from +n). **Deliberately NOT the
  as-shipped `src/qa023_probe.zig` `fixpoint_kernel`**, whose White-node update
  guards are inverted (pinrule-sufficiency §1: L sweep updates a White node only
  when the child-min is *smaller* than the current value — impossible from the
  −6 floor; H sweep symmetric). That bug is **still at HEAD** (verified by grep
  in this task: `src/qa023_probe.zig:965` `best < L_tab[li]`, `:1024`
  `best > H_tab[hi]`). See §8.
- **History generators** — (a) BFS shortest paths from the root, enumerated as
  a set via DFS over the shortest-path DAG; (b) randomized-DFS detours (the
  probe-equivalent generator, depth-capped, strictly longer than the shortest);
  (c) the old-style DFS-only generator retained as the baseline control.
- **Truncated evaluators** — first-revisit truncation per
  `reference-semantics-2026-07-29.md` §1 (arrival visit set exclusive of σ;
  TIE on revisit of arrival-or-path; area at passes==2; budget-capped, exhaustion
  never agreement). Two exact variants: plain minimax (bitset) and alpha-beta;
  alpha-beta is primary (the handcheck's own trees are alpha-beta trees).
- **Controls** — null (same state, same history, evaluated twice) and seeded
  (value consults the arrival itself; probe must catch it).
- **Modes**: `census`, `witness`, `contrast`, `probe`, `control-null`,
  `control-seeded`; six tagged tests.

## 2. Instrument validation — the known answers reproduce

### 2.1 The hand-verified witness (3×2), reproduced exactly

State **(178,0,6,0)** = `[B W B . W .]`, Black to move, ko=none, passes=0 —
the single witness the QA-023 C1 falsification rests on
(`c1-witness-handcheck-2026-07-29.md`, two independent implementations,
node-for-node agreement). With the alpha-beta evaluator:

| arrival | moves | states | value | nodes | handcheck |
|---|---|---|---|---|---|
| A: `B2 W3 B1 W4 B5 pass B0 pass B3 W4 pass W5 B0 W3 pass W1 pass W2 B0 W1 B2 W4` | 22 | 23 | **−3** | **22** | −3, 22-node tree |
| B: `B3 W1 pass W5 pass W4 pass W0 pass W3 B2 W3 B5 pass B0 W4 B1 pass B3 W4 B0 pass B2 W1` | 24 | 25 | **−6** | **33** | −6, 33-node tree |

Both arrivals validate as legal simple paths (ARRIVAL-VALID=0, ends-at-σ=true,
σ-in-arrival=false). The alpha-beta node counts (22 and 33) match the
hand-verified trees **exactly**, and the −3/−6 values match. Plain minimax
exhausts a 20M-node budget on the same evaluation — the handcheck's ">100K
nodes" estimate, and the reason alpha-beta is the primary evaluator (it is
exact: pruned nodes cannot change the root value).

Mechanism (per the handcheck): arrival A's visit set contains the pivotal state
**(9,1,6,0)** = `[. . B . . .]` (its move-1 destination); when the continuation
reaches that state, first-revisit truncation scores TIE=0, which changes White's
minimisation at the interior MIN node and lifts the root from −6 to −3. Arrival
B does not contain it; the same node evaluates to −6 and the root is −6, matching
the (history-free) fixpoint L==H==−6.

Run: `3x2 contrast --n-states 100 --seed 0x2B3DA7A` (100 flat-sampled
non-terminal states; old-style generator depth 16, k 8 — the 2B-3 config).

| metric | 2B-3 baseline (old DFS) | OLD generator re-run here | NEW generator |
|---|---|---|---|
| shortest-arrival hit rate | 7% (93% miss) | **2/100 = 2% hit** (98% miss) | **100/100 = 100% hit** |
| avg arrival length | 14.8 (shortest 5.1) | 15.21 | shortest **5.87**, detours 23.09 |
| pairwise shared prefix | 62.35% | 52.91% (2,716 pairs) | **23.44%** (2,278 pairs) |
| ARRIVAL-BAD (validated subset) | — | — | **0** |

The old-style generator re-runs on my machine reproduce the systematic bias
(98% miss, ~53% shared prefix, ~15-move arrivals) — the baseline is real, not a
stale citation. The new generator **beats it decisively on every axis**: every
sampled state gets a genuine shortest arrival (guaranteed by construction, and
the measurement confirms the guarantee), and the short-vs-detour pairing drops
the shared prefix from ~53–62% to 23.4%. This is the contrast the 2B-3 audit
said the C1 test was missing: the short-direct vs long-wandering comparison.

Per the brief's bar: the generator beats the baseline, so it is a result, not a
defect. (Had it failed to beat the baseline this row would have stopped here.)

## 4. Controls — run before the reading counts

### 4.1 Null control — the harness is deterministic

Run: `3x2 control-null --n-states 64 --seed 0x2B3DA7A`.

> null control: 64 (state, history) pairs evaluated twice; mismatches **0**;
> replay mismatches **0** → **PASS**

Same state, same history, two fresh evaluations (and the arrival replayed twice):
identical. A mismatch here would mean the harness, not the theory, is broken.

### 4.2 Seeded control — the probe catches injected history dependence

Run: `3x2 control-seeded --n-states 96 --seed 0x2B3DA7A` and
`3x3 control-seeded --n-states 128 ...` (general stratum, budget 5M).

The value is perturbed so it **consults the arrival itself** (outside the four
key components), then the same probe pipeline must flag C1 failures:

| seed | 3×2 | 3×3 |
|---|---|---|
| `len_gt_dist` (value +1 iff arrival longer than the shortest) | **152 disagreeing pairs / 10 C1-fail states — DETECTED** | **32 / 2 — DETECTED** |
| `pass_member` (value +1 iff arrival contains a pass) | **8 / 1 — DETECTED** | 0 / 0 — feature uniform in the 3×3 within-budget sample |

**Verdict: PASS** at both gobans — the probe discriminates an injected
history-consulting oracle. A probe never shown to fail is not evidence; this one
fails loudly on both sizes.

**Instructive negative control.** The first seed tried was *arrival-length
parity* (`value += len & 1`). The probe correctly did **not** flag it — because
path-length parity is **a function of the state tuple itself**: side toggles on
every move from the root, so length parity ≡ side. It is not a history
consultation, and the probe's non-detection of it is exactly right (the
within-budget debug trace showed uniform parity per state). This is recorded as
a caution: a "history" feature that is secretly a tuple function must not be
used to calibrate a sufficiency probe.

## 5. The C1 probe readings — with denominators

Semantics of the counts: a history evaluation is **within-budget** iff the
truncated evaluator returns a value (never on exhaustion — exhaustion is a
separate count). **C1-eligible** state = ≥2 within-budget evaluations at the same
state (its histories can actually be compared). **C1 failure** = two within-budget
values at the same state disagree. **Fresh-start cut** = the shortest-arrival
values only, compared with the corrected fixpoint median `median(L,TIE,H)`.

### 5.1 3×2 (the rung with the witness)

Run: `3x2 probe --n-states 128 --seed 0x2B3DA7A --k-short 4 --k-detour 4
--max-depth 24 --budget 5,000,000 --eval ab` (129 states: 128 sampled + the
witness state (178,0,6,0) forced in).

- **N states × M pairs**: 129 states sampled, 129 reached; 906 histories
  (441 shortest, 465 detours), ARRIVAL-BAD 0, σ-in-arrival 0; 906 evaluations,
  **142 within-budget, 764 exhausted (84.3%)**; **404 within-budget history
  pairs** across 24 C1-eligible states.
- **C1: 0 failures** — zero disagreeing pairs of 404 (0/24 states).
- **C2: 0 failures** — all within-budget values equal `median(L,TIE,H)` (0/24
  states).
- **Fresh-start cut: 66/66** within-budget shortest-arrival values equal the
  corrected fixpoint median.

**The [F] verdict at 3×2 is two-layered and must be read as such:**

1. **The [F] exists and reproduces** — the hand-verified witness (178,0,6,0)
   gives −3 under arrival A and −6 under arrival B (§2.1). Under the
   history-conditioned first-revisit-truncation rule, C1 **fails** at 3×2:
   the `(position, side, passes, ko)` tuple is not a sufficient Markovian state
   for that rule. This was settled by QA023-C1-WITNESS (hand-verified, two
   independent implementations) and is **reproduced exactly** by this task's
   independent instrument.
2. **The sampled probe found no *additional* [F] at this contrast level** —
   0/404 pairs, 0/24 states disagree. The witness pair itself was not re-drawn:
   the generator's randomized detours to (178,0,6,0) did not happen to include
   the two specific 22/24-move arrivals A and B (the disagreement requires the
   visit set to contain the specific pivotal state (9,1,6,0)). The witness is
   reproduced deliberately in witness mode (§2.1), not by random sampling. This
   matches pinrule's own note that its 7-witness census is a **lower bound** on
   the obstruction's extent (75.5% exhaustion there, 84.3% here).

So the honest one-line statement: **the node's [F] is FOUND at 3×2 — the
hand-verified witness reproduces exactly — and the contrast-rich sampled probe
found no further witnesses within its denominator (24 states, 404 pairs, 142
within-budget evaluations).**

### 5.2 3×3 (new measurement; per-goban independence applies)

- **C1: 0 failures** (0/80 pairs). **C2: 0 failures** (0/6 states).
- **Fresh-start cut: 24/24** shortest-arrival values equal the corrected median.

Run 2 — sparse stratum (≤2 empty cells, budget 20M; a completable sub-population
for cross-check): 64 states, 144 evaluations, 4 within-budget, 1 C1-eligible
state, 6 pairs, **0 failures**; fresh-start cut 0/0 (no shortest values

**3×3 [F] verdict: NOT FOUND within the within-budget denominator** (6 eligible
states / 80 pairs in the general stratum) — with 93.3% exhaustion honestly
stated; the 3×3 reading is a lower bound on a larger state space (V=73,755) and
carries no weight as a "pass" beyond its own denominator. The fresh-start cut is
**consistent on every within-budget shortest-arrival value** at both 3×2 (66/66)
and 3×3 (24/24).

## 6. Cross-check: T2 plain-minimax vs T3 alpha-beta

The witness mode evaluates both arrivals with both evaluators (alpha-beta
completes at 22/33 nodes; plain minimax exhausts even 20M nodes — the honest
exponential cost the handcheck documented). The values are exact under both
(alphabetical pruning cannot change a minimax value); the hand-verified trees
are themselves alpha-beta trees, so alpha-beta is the primary instrument and
plain minimax is a provenance cross-check, exactly as in pinrule-sufficiency
(T3 primary, T2/T3 cross-checks 79/0 there; the Python verifier reproduced T3).

## 7. Findings — things this task surfaced

1. **The triage's §5.1 "fresh-start reading is still untested" is stale.**
   `pinrule-sufficiency-2026-07-29` already tested it: 396/396 shortest-arrival
   values equaled `median(L,TIE,H)` with the corrected tables, and §4b's
   "fresh-start surprise" is that exact cut. This task re-tests the same cut
   with a measured-contrast generator and the mandated controls — 66/66 at 3×2
   and 24/24 at 3×3 — but the register-triage sheet should not cite the
   fresh-start reading as *untested*. (No claim status is changed here;
   `claims: []`.)
2. **`src/qa023_probe.zig`'s fixpoint kernel is still broken at HEAD.**
   pinrule-sufficiency reported the inverted White-node update guards at HEAD
   `8b610ee`; this task verified by grep that `:965` (`best < L_tab[li]`) and
   `:1024` (`best > H_tab[hi]`) are still the guards at HEAD `657f800`. The
   published probe fixpoint pins L=−6, H=+6 at every White non-terminal state.
   Any future probe reading that uses `fixpoint_kernel` for its reference is
   invalid; the corrected kernel is `fixpoint_corrected` (this file and
   `src/qa023_pinrule.zig`). The file is held by 2B-6/F1-SEEDROOTS — reported,
   not edited.
3. **The degenerate-parity trap** (§4.2): length-parity looks like a history
   feature and is a tuple function (side toggles every move). A sufficiency
   probe calibrated on it would be calibrated on a non-seed.
4. **Budget exhaustion is the honest cost and is state-dependent**: 84.3%
   (3×2) and 93.3% (3×3) of evaluations exhausted within budget; the
   within-budget fraction is a lower bound on where the C1 reading has power.
   This is the same shape as the 2B-3 and pinrule measurements, not a new story.
