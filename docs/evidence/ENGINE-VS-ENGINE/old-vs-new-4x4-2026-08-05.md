# T366 — old 4×4 engine vs new 4×4 engine: where the old one loses (the divergence kifu)

Task: T366 · Role: worker · Model: deepseek-v4-flash · Date: 2026-08-05

Milestone M3 of the reconstruction: the WZO1-era 4×4 oracle
(`data/oracle-4x4.checkpoint.wzo`, SHA `a2174fed…`) against the current WZO2
oracle (`data/oracle-4x4-v2.wzo2`, SHA `0c3366f0…`), played head-to-head, with
the kifu of where they diverge. Every number below cites its run: seed 42,
33 openings × 2 colour assignments × 2 legality frames = 132 games, all
replayed and cross-checked against a separately built binary.

---

## 1. The two artifacts encode different rulesets — scope the comparison

This is the first thing to say plainly, because a comparison across two
different games is not a result.

| | old (`oracle-4x4.checkpoint.wzo`) | new (`oracle-4x4-v2.wzo2`) |
|---|---|---|
| format | WZO1 (2026-07-21 checkpoint) | WZO2 |
| rules_id | 1 — Chinese area, komi 0, positional superko | 3 — Chinese area, komi 0, basic ko, L/H bracket |
| key | (goban, side) only — no ko point, no pass count | (goban, side, ko_point, passes) full Markov key |
| stored value | one fresh-start score | L/H bracket + DTT per key state |
| known status | **the writes-ON build** — its ko-sensitive values are the untrusted ones (AGENTS.md foreclosure) | current artifact, the Z-bar |

The old engine's stored values are *fresh-start* values under PSK; the new
engine's stored values are *fresh-start* values under basic ko, keyed on the
pending-ko/pass state. The comparison is therefore scoped:

- **Play** is always a single coherent game per frame (frame A: shared PSK
  legality; frame B: the new ruleset, basic ko — the old engine still filters
  its own moves by PSK, its table's rule).
- **Stored-value comparisons at a node** are reported only with the node's
  `(ko, passes)` state, and flagged `in-scope` when it is the fresh-start
  slice (ko = none, passes = 0) where both engines' values are directly
  comparable. 62 of 66 first divergences per frame fall in that slice.
- Even in the slice, PSK vs basic-ko differences *downstream* legitimately
  change values at ko-reachable positions. Value differences are therefore
  never counted as losses by themselves. **Only an outcome difference decides
  the classification.**

## 2. Method

**Instrument** — a new standalone tool, `src/t366_evse.zig` (SHA
`60f1b41e…`), compiled ad hoc with `zig build-exe` at HEAD `95b2eff`
(build.zig untouched; engine sources untouched; reads both artifacts only).
It reuses the committed session/table code (`gtp.zig`, `rules.zig`,
`artifact.zig`, `artifact2.zig`). Full invocation:

```
zig build-exe -O ReleaseFast --dep version -Mroot=src/t366_evse.zig \
  -Mversion=src/version.zig --cache-dir /tmp/weizigo/t366/cache \
  --global-cache-dir /tmp/weizigo/t366/global --name weizigo-t366-evse \
  -femit-bin=docs/evidence/RESCUED-tmp-2026-08-08/t366/t366-evse
docs/evidence/RESCUED-tmp-2026-08-08/t366/t366-evse --frame both --openings 30 --seed 42 \
  --out docs/evidence/ENGINE-VS-ENGINE --json findings/T366-engine-kifu.json
```

**Openings** — 3 canonical one-ply openings (Black's first move only,
White to move after: corner A1, edge B1, centre B2) + 30 seeded random
two-ply openings (deduplicated; 33 distinct). Every opening is played twice:
old-as-Black and old-as-White. The opening plies are forced for both engines;
play then continues with each engine choosing for its own colour.

**Two frames**:
- **frame A** — the new engine's move selection PSK-enforced too: a shared
  PSK game, the comparison the existing `engine-vs-engine` tool would make.
- **frame B** — the new engine plays its own ruleset (basic ko); the old
  engine's moves remain PSK-filtered. This is the frame that matters for the
  Z-bar: *can the old engine keep up in the world we actually play?*

**Divergence** — at every ply both engines' choices are computed; the first
ply where they disagree is the marked node, recording both engines' chosen
moves and their stored values (old: node V0; new: node L/H bracket at its own
(ko, passes) key), plus the node's ko class (0/1/2/3+ independent kos) and
in-scope flag. The move actually played is the side-to-move engine's choice.

**Classification** (outcome-based, the brief's "does it actually lose or does
it choose a different move of equal value"):
- `genuine_loss` — the old engine lost (or drew) a game its colour could have
  won (or drawn) under better moves: the substitution replay (the
  `engine-vs-engine` regression semantics: the new engine's moves at the old
  engine's decision points, the original opponent moves replayed) wins with
  the old engine's colour, or — when that replay diverges — the new-engine
  self-play arbiter from the same opening wins/draws with the old engine's
  colour.
- `loss_not_attributable` — old engine lost, but even the new engine's moves
  with its colour from the same opening lose: the position was lost anyway.
- `equal_value` — old engine did not lose (won, or held a draw the new-engine
  line also holds): the divergence did not cost the game.
- `outcome_unknown` — substitution replay diverged and the arbiter cycled to
  the ply cap (basic-ko position cycling, TIE=0).

**Verification** — every one of the 132 games was replayed through
`bin/weizigo-gtp` (a binary built separately from the instrument at the same
commit; SHA `d8202063…`): the divergence node's OLD/NEW choices match
`weizigo_chaincheck` at that node, every fully replayable game's final score
matches, and frame-B cross-ruleset plys are rejected by the GTP `play`
superko gate at exactly the recorded plys. Result: **132/132 OK, 0 failed**.
(Caveat: GTP `play` enforces positional superko unconditionally, so frame-B
lines containing position repetitions cannot be replayed through GTP; the
instrument's in-process play — `applyMove`, no play-time PSK check — is the
authority for those lines, matching the basic-ko ruleset the artifact encodes.
The first verification attempt skipped the SGF→GTP coordinate conversion and
is discarded.)

### 4.1 Frame A — the old engine loses to itself (its own table is internally inconsistent)

These three are the cleanest evidence: same ruleset on both sides, no
cross-ruleset moves, and the old engine still throws away a winning position.

**fA-o32-W** — the largest throw: at the divergence node (ply 2, Black to
move) *both* tables say White is +16 (`old-V0 = −16`, `new L = H = −16`). The
new engine (Black) played dc; the old engine, from its own subsequent White
moves, lost B+3 — a 19-point swing from a position its own table called won
by 16. The arbiter confirms W+16 is real: the new engine wins by 16 with
White from this opening.

```
(;GM[1]FF[4]CA[UTF-8]AP[weizigo-t366-evse]RU[Chinese]KM[0]SZ[4]C[T366 divergence kifu. frame=fA old-colour=White opening=random-029-ddcc result=B+3 old-result=loss classification=genuine_loss];B[dd];W[cc];B[dc]C[DIVERGENCE ply2: OLD would play aa child-value -16; NEW plays dc child-value -16. node old-V0=-16 new-L=-16 new-H=-16 ko=0 passes=0 in-scope=yes];W[ba];B[cb];W[bb];B[bc];W[db];B[cd];W[ca];B[da];W[ac];B[db];W[ab];B[bd];W[];B[])
```

**fA-o21-B** — the old table contradicts itself: at the divergence node
(ply 6, Black to move) the old engine's stored V0 is **+1** (Black winning),
but its chosen move `ac` has child value **0** — no child (and no pass) in its
own table achieves its own node value. The new engine's `dc` achieves 1. The
arbiter: B+1 was there, the old engine lost W+3.

```
(;GM[1]FF[4]CA[UTF-8]AP[weizigo-t366-evse]RU[Chinese]KM[0]SZ[4]C[T366 divergence kifu. frame=fA old-colour=Black opening=random-018-dbbc result=W+3 old-result=loss classification=genuine_loss];B[db];W[bc];B[bb];W[cc];B[cb];W[ab];B[ac]C[DIVERGENCE ply6: OLD would play ac child-value 0; NEW plays dc child-value 1. node old-V0=1 new-L=1 new-H=1 ko=0 passes=0 in-scope=yes];W[ad];B[dc];W[ba];B[ca];W[cd];B[aa];W[ac];B[];W[ba];B[];W[])
```

**fA-o19-W** — equal node values, different outcome (the subtle one): at the
divergence node (ply 5, White to move) both engines' pinned values are −1
(White +1); the new bracket is [−16, −1] and the new row is
**ko-sensitive** — the position is ko-reachable downstream. The old engine
played db, the new engine would play dc; from db the old engine's line
collapsed to B+3. Value equality at the node does **not** imply outcome
equality — this is exactly the class of error the writes-ON build is known to
make in ko-sensitive regions.

```
(;GM[1]FF[4]CA[UTF-8]AP[weizigo-t366-evse]RU[Chinese]KM[0]SZ[4]C[T366 divergence kifu. frame=fA old-colour=White opening=random-016-adcb result=B+3 old-result=loss classification=genuine_loss];B[ad];W[cb];B[bc];W[bb];B[cc];W[db]C[DIVERGENCE ply5: OLD would play db child-value -1; NEW plays dc child-value -1. node old-V0=-1 new-L=-16 new-H=-1 ko=0 passes=0 in-scope=yes];B[ab];W[dc];B[ba];W[ca];B[cd];W[aa];B[ac];W[];B[ba];W[];B[])
```

### 4.2 Frame B — the old engine loses to the new ruleset (position repetition)

The four additional frame-B losses (fB-o02-B, fB-o04-B, fB-o06-B, fB-o17-B)
share one mechanism, visible in the recorded cross-ruleset plys:

- the old engine (Black) is winning or even (+1 per the arbiter — the new
  engine wins Black +1 from the same opening);
- the new engine (White), under basic ko, plays **position-repeating moves in
  the endgame** (e.g. fB-o04-B plys 15 and 17: White repeats whole-board
  positions — legal under basic ko, illegal under PSK, marked in the kifu);
- the old engine's PSK rule and PSK-era table cannot answer — it passes out
  and loses 0–16.

The kifu files mark these plys with a `NOTE: this move repeats a position the
old engine's PSK rules forbid (cross-ruleset ply)`. Example (fB-o04-B, old
Black, result W+16):

```
(;GM[1]FF[4]CA[UTF-8]AP[weizigo-t366-evse]RU[Chinese]KM[0]SZ[4]C[T366 divergence kifu. frame=fB old-colour=Black opening=random-001-dddc result=W+16 old-result=loss classification=genuine_loss];B[dd];W[dc];B[bc]C[DIVERGENCE ply2: OLD would play bc child-value 2; NEW plays cc child-value 1. node old-V0=2 new-L=1 new-H=16 ko=0 passes=0 in-scope=yes];W[cb];B[cc];W[bb];B[db];W[ac];B[ca];W[bd];B[ba];W[ab];B[];W[cd];B[ad];W[bd]C[NOTE: this move repeats a position the old engine's PSK rules forbid (cross-ruleset ply)];B[];W[cd]C[NOTE: this move repeats a position the old engine's PSK rules forbid (cross-ruleset ply)];B[];W[dc];B[];W[da];B[];W[aa];B[];W[])
```

This is the honest reading of the Z-bar: in the world we actually play
(basic ko, current ruleset), the old engine cannot handle an opponent who
repeats positions, and four openings in sixty-six turned that into losses
the new engine would not take. The three frame-A losses carry over to frame B
unchanged (they are old-table defects, not ruleset effects).

## 5. What this means — and what it does not

- **Where the old 4×4 engine loses:** (1) its own table contradicts itself —
  node values its children cannot reach (fA-o21-B), and lines that collapse
  from winning positions (fA-o32-W, fA-o19-W) — consistent with the
  checkpoint being the known-untrustworthy writes-ON build; (2) in the new
  ruleset it cannot answer basic-ko position repetition (fB-o02/o04/o06/o17).
- **Rate:** 3 of 66 games (4.5%) in the shared-PSK frame, 7 of 66 (10.6%) in
  the new-ruleset frame — at these openings. Most old-engine losses (33 of
  36 / 33 of 40) are openings lost for its colour regardless of who plays it.
- **Every divergence is still reported** — 66 per frame — with both engines'
  moves and stored values at the first-disagreement node, in the SGF files
  and the machine-readable kifu JSON. Only the *outcome-based* classification
  says which ones cost the game.
- **What this does not claim:** no table value here is a real-game value —
  everything compared is the fresh-start slice (C1); real-game
  history-independence (C2) is falsified at 3×2 and is out of scope. The new
  engine's L/H values at ko-pending or pass states are reported as data, not
  used as the basis for a loss verdict.

### 5.1 Is the new engine strictly better? The mirror measurement

Not by raw results: the old engine **won** 30 of 66 games in frame A and 26
of 66 in frame B, often whole-board (B+16 ×24 / ×20). The games are
opening-driven — raw win rate mostly measures who drew the better side of the
opening, so it is the wrong lens.

The right lens is throw-aways, and there the answer is one-sided. Running the
exact same outcome test with the roles swapped (the old engine's substitution
replay and self-play arbiter, played with the new engine's colour):

| frame | old engine (tested) | new engine (tested) |
|---|---|---|
| fA | 3 genuine losses of 36 | **0** genuine losses of 30 |
| fB | 7 genuine losses of 40 | **0** genuine losses of 26 |

On this sample, wherever a game was winnable or drawable for the tested
colour, the new engine won or drew it — and the old engine sometimes did not.
The old engine's defects are real; the new engine's are not detected.
Caveats: the frame-B mirror tests the old engine's PSK world (its only
world), so it bounds rather than equals the basic-ko question; and "0" is
"none detected in 66 games per frame", not a proof. The mirror numbers are
in the kifu JSON (`mirror_summary`, per-game `mirror` records).
