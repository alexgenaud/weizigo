## Root cause

**Bug in `src/oracle_v2_build.zig` line 387:** the passes=1 entries are encoded
with `passes=0` in the key_byte.

```zig
// Line 387 — BUG: passes argument is 0, should be 1
const kb_val = artifact2.encodeKeyByte(side, exp6.KO_NONE4, 0, 0, kb);
//                                                   BUG ^—— should be 1
```

This causes passes=0 and passes=1 entries for the same (board, side, ko=KO_NONE)
to share identical key_bytes, producing two failure modes:

1. **A9 entry sort:** passes=1 entries interleave with passes=0 entries at the
   same sort key (0x40/0x42 for KO_NONE), breaking monotonic order. One
   violation per (board, side) = ~24.3M.

2. **A3 colour inversion:** the lookup for the inverted key finds the wrong
   entry — it may retrieve the passes=0 entry's L/H when the passes=1 entry
   was needed, or vice versa. ~16.3M mismatches.

## Fix

One-character change in `src/oracle_v2_build.zig` line 387:

```diff
-                const kb_val = artifact2.encodeKeyByte(side, exp6.KO_NONE4, 0, 0, kb);
+                const kb_val = artifact2.encodeKeyByte(side, exp6.KO_NONE4, 1, 0, kb);
```
