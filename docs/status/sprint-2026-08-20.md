## The bar — per bug, non-negotiable

The operator set three conditions and they are the sprint's acceptance, not advice:

1. **Reproduce before fix.** No fix lands without a command that demonstrates the defect
   first. If it cannot be reproduced, it is not yet a bug — record it as an observation with
   its denominator and move on. This is the project's own rule ("never trust a green test"):
   an instrument needs a null control and a seeded-defect control before its first reading
   counts.
2. **Red then green.** The regression is written before the fix, is observed FAILING against
   current code, and that red observation is quoted in the findings. A regression first seen
   green proves nothing.
3. **Findings with denominators.** Every count states what it is out of, and the command that
   produces it. "34 rows" is not a finding; "34 of the 49 rows whose bundle declares `holds=`,
   measured by <command>" is. The L1 bar's load-bearing clause is *every gauge number
   reproducible by the command the doc names* — this sprint is where that habit is enforced.

## The sweep — defects found at boot, each needing a row

Each is stated with the evidence that found it. Sub-delegate one row per item; some are
one-liners with a hard control, which is exactly the shape this sprint wants.

1. **Mutating verbs silently ignore unknown flags.** `bin/managent next --peek` — there is no
   `--peek` flag — ignored it and **claimed a row** (`ORCHA-FLASH`, reverted). A mutating verb
   that accepts a flag it does not understand cannot be operated safely. Refuse unknown flags
   (exit non-zero naming the flag), at minimum on every mutating verb. Control: a seeded call
   with a bogus flag must refuse and leave the store byte-identical.
   *Denominator to establish: how many verbs accept unknown flags today, out of how many verbs.*
2. **The keeper keeps its own model list, and the list has no Claude labels.**
   `tools/fleet-keeper.sh:247` hardcodes `["kimi-k2.7","minimax-m3","deepseek-v4-flash",
   "deepseek-v4-pro","glm-5.2"]`, so `least_data_model()` can never hand a model-less row to a
   Claude lane — the other half of audit F7. `T517` shipped `managent models [--json]` as the
   single source precisely for this; make the keeper consume it. Note the roster is now 7 lanes
   including four Claude labels (`docs/epics/E1-markovian/L1-dashboard/S02-model-delegation/grand-race.md` §2, epoch `2026-08-20b`), so
   the omission now biases the race data too.
3. **A misleading pre-commit diagnostic.** The hook printed `no task identity … and no live
   holders known (kanban unreadable or empty)`. The kanban was readable; `holds` was empty
   everywhere (the `T539` defect). The message named the wrong cause, which is how a real
   signal gets ignored. Distinguish "cannot read the store" from "store read, no holders
   declared" — they need different reactions.
4. **`managent suggest` mints a row whose header nothing validates.** It writes
   `<!--managent set=A deliverables=-->` and the author fills in `deliverables=`/`holds=` by
   hand afterwards, with nothing checking that the header and the store agree — the mechanism
   behind `T539`. Either validate at dispatch or generate the header from the store. Coordinate
   with `T539`; do not duplicate it.
5. **Wall budgets are set by the dispatcher's guess and the advisory only warns after.**
   T514/T517/T518 were each dispatched at `--wall=1800` and each drew
   `wall-low: … < recommended 3600s` (T518: `class=verification … recommended 5400s` for a
   1472-byte brief). The advisory worked; the dispatch had already happened. Make
   `bin/dispatch` default to `recommended_wall()` for the row's class instead of a flat 2700,
   and check whether the classifier is over-eager (a 1.4 KB findings-only brief classified
   `verification`/5400 s looks wrong). Ties to `T520`.
6. **`untracked/runs/` straggler reconciliation — the handover's number does not reproduce.**
   The incoming pack's correction note asserted *"30 such files exist in `untracked/runs/`"*
   with the denominator never stated. Measured 2026-08-20 12:20Z: **43 files total — 40
   task-id-named, 2 deliberate `T449-*` regression fixtures, and exactly 1 pid-named
   (`runner_93345.json`, 13:18 local)**. `T515` (task-id-named run records, commit `6d5eee0`)
   landed and evidently cleaned the rest. Close the loop: state the number, say whether the 1
   remaining is pre- or post-`T515`, and delete it or explain why it stays. This item is
   *bookkeeping with a stated denominator* — treat it as the worked example of condition 3.
7. **`directives.jsonl` accumulates blank lines.** Two blank lines were appended during boot
   (workers running `inbox --ack`). Harmless today, but it is an append-only evidence file and
   junk lines in evidence files are how parsers start guessing. Cheap fix, needs a control.
8. **A running-script rewrite hazard.** `bash` reads a script incrementally from disk, so
   restarting `tools/fleet-keeper.sh` while a worker rewrites it risks executing a partially
   written file. This is why the seat left the keeper stopped rather than restarted during
   `T536`. Decide the mechanism — the keeper `exec`s a snapshot of itself, or a start wrapper
   copies-then-runs — and record the decision even if the answer is "accept the risk, document
   it".
9. **A naive single-instance guard will false-positive.** `pgrep -f fleet-keeper` returned **2
   while zero keepers ran**, matching the T536 and T514 *worker* command lines (their briefs
   name the file). `T511` owns the single-instance guard; this sprint's job is to make sure
   `T511` does not ship that bug. Control: the guard must return 0 with a worker running whose
   brief mentions the keeper.

## Keep-hunting (same technique, next findings)

- **Store writes reorder JSON keys.** A `managent next` claim of one row (ORCHA-FLASH) produced
  **64 changed diff lines** in `tasks.json` while only **1 row** changed semantically (verified
  by Python dict compare). The Zig map serializer writes keys in a different order than the file
  it read, so every single-row mutation is a noisy diff that obscures `git diff` attribution —
  the exact hazard `docs/infra/fleet-git-isolation.md` names. Observed, not fixed (would touch
  `src/managent/main.zig`, held by T539).
- **`suggest` mints a row on an unknown flag** (`suggest --T540-BOGUS` → T543) — folded into
  item 1 above (same root: no unknown-flag rejection path on any mutating verb).
- **`suggest` writes bundle + row non-atomically, to two different roots.** `cmdSuggest` writes
  the bundle to `repo_root/untracked/` (discovered from cwd) but registers the row in
  `state_path` (relocated by `MANAGENT_STORE`). A probe against a scratch store therefore still
  wrote **live orphan bundles** (`T542---T540-BOGUS.md`, `T543---T540-BOGUS.md`) that later
  collided with legitimately minted `T542`/`T543` and blocked their dispatch — the T445
  live-repo-escape class. Preserved as `untracked/ORPHAN-*.evidence`. This is my own probe's
  artifact (D037); recorded, not hidden.
- **Directive IDs are reused.** `D036`–`D042` each appear twice in `directives.jsonl` with
  different targets (e.g. `D037` → T363 and `D037` → T540), so the directive counter was reset
  or collisions are unguarded — an append-only evidence file whose IDs are not unique.

## Probe-hygiene correction (D037)

Directive `D037` (2026-08-20T12:38:37Z) ruled: **probe mutating verbs against a scratch
`MANAGENT_STORE` *and* a scratch root, never the live store** — the store override relocates the
row but not the bundle/directives/heartbeat files, so a scratch store alone is not enough
(that is exactly how the `T542`/`T543` orphan bundles escaped to the live `untracked/`).
The rule holds for the rest of this sprint and any future probe.
