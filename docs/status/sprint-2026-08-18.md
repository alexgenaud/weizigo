## The gate's first independent run went RED, and it was right to

`sh tools/suite-truth.sh`, run by Orcha hours after T369 closed. Verdict: **RED**, naming
`tools/regression-git-commit-mine.sh` under *"FIXED (in manifest, no longer failing)"* — the
struck-red direction, which is the half of a ratchet nobody usually exercises.

The cause, measured in both arms at `f8983bb`:

```
env -u MANAGENT_TASK_ID sh tools/regression-git-commit-mine.sh   → rc=0, 0 FAIL
MANAGENT_TASK_ID=T369    sh tools/regression-git-commit-mine.sh  → rc=1, 6 FAIL
```

`zig build test` therefore has **7 failing steps under a task identity and 6 without**, and the
manifest records the 7-red set unconditionally. A dispatched worker (`bin/subagent` exports
`MANAGENT_TASK_ID`) reads GREEN; the Orchestrator running the same gate by hand reads RED. **A
gate that answers differently for two honest callers is the same disease one level up** — which
is what T369 was created to cure.

T369 diagnosed the mechanism exactly right: `MANAGENT_TASK_ID` leaks into the scratch repo, so
`tools/git-commit-mine` resolves the live task id against a scratch kanban. What it could not
see is that its own controls were green *because they ran under its own identity* — the precise
shape of "never trust a green test", caught only because someone else ran the same gate from a
different shell. Registered as **T454**; T369 carries a post-close amendment, verdict unchanged.

**Positive control worth recording alongside it:** the tree was byte-identical before and after a
full suite run — no `T425-DOCTOR-*` fixtures, no `C10-*-SEEDED.md`, and `AGENTS.md` carried zero
seed lines. The T448 residue class needs a *killed* run to fire, and a clean run does not leave
it behind.
