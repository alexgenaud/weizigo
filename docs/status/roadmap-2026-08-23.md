## 0. The root cause this roadmap answers

Operator diagnosis, 2026-08-23, recorded because it is the organising idea:

> *"We must consider every script and binary as a mini-software project, aka a module. … We lack
> unit tests and regression tests and e2e use case test suites. … I keep talking about spec-do-verify
> bookends, but that's EXACTLY what acceptance tests and unit tests and integration tests are for.
> Not just approval before and after implementation, but long term guarantees of stability. I should
> not WONDER why qwen takes down tasks, but guarantee that it does not. … I have no confidence
> anything works as is and certainly no confidence anything will work after consolidation … that is:
> no confidence without TEST SUITES."*

**Measured state, 2026-08-23** (the numbers that make this a gate problem, not a test-writing
problem):

| surface | count |
|---|---|
| regression scripts in `tools/` | 80 |
| test steps in `build.zig` | ~130 (777/778 passing at last baseline) |
| modules in `bin/` + `tools/` | 40 (11 + 29) |
| modules no regression script even names | **13** |
| gate mechanism | **exists** — `tools/suite-truth.sh`, observed-vs-manifest, ratchet-down only |
| what runs it automatically | **nothing** — no CI, no cron, no launchd agent |
| what `tools/hooks/pre-commit` gates on | claimlint citation debt only; it invokes **no test** |

So the tests largely exist and **nothing re-runs them**. The worked example is T711: its
host-guard control passed the day it was written, was never re-run, and the case it did not cover
killed three fleet lanes three days later. Green at the moment of writing, never again.

**The correction that sets the work order.** Every failure of the week 2026-08-17→23 was a *seam*
or an unasserted *contract*, not a unit-level bug — a local model co-launched with cloud lanes and
the guard killed three innocent lanes; two lanes exited 0 without reading their bundles; a repair
row rewrote a race's sealed inputs mid-race; `managent done --verdict X` silently recorded `pass`
because `done` takes `--status` and unknown flags are ignored; the token meter called 448
recoverable readings unattributable. A unit test would have caught **none** of them. Therefore:
**e2e and contract first, unit second.**

## 1. The test-suite project — four rows, strictly sequenced

The sequence is the operator's own rule applied to itself: *"we need to prove what works works
before proving the consolidation still works."*

### T788 — re-baseline the test suite · IN FLIGHT (`deepseek-v4-pro`)
**Why:** nobody knows how red the suite is. `docs/infra/suite-truth.md`'s baseline is the run of
2026-08-21 00:13Z, and its own headline red (the four-module `rules.zig` root/engine compile
conflict) is marked STRUCK 2026-08-22 by T530. Of its four shell reds, two the manifest itself
calls one-line re-points, one is state-dependent and owned by T442, one is a live defect
(`regression-watch-fleet` arms F/G). The manifest has read as authoritative for two days while
being wrong.
**Bar:** quiet host (no resident local model, no in-flight lanes — an 18 GB MLX load takes the
machine to load ~9.5 and contamination is what produced the bogus 35–52 minute readings of
2026-08-08); one guarded `sh tools/suite-truth.sh` run at `-Doptimize=ReleaseSafe`, log captured,
start-time load and free memory recorded; manifest re-baselined so the gate exits 0.
**It must report the five numbers T789's design needs:** total wall · fast-subset wall
(`tools/smoke.sh`) · how many checks are deterministic vs state-dependent · how many need a quiet
host · which reds belong to other rows.

### T789 — wire the test gate · blocked on T788
**Why:** see §0. The mechanism exists; nothing invokes it.
**Three tiers, because one gate cannot serve all three:**
1. **pre-commit** — fast, deterministic, host-insensitive, with a stated hard budget. A
   pre-commit gate that takes minutes gets bypassed, and a bypassed gate is worse than none
   because it teaches the bypass.
2. **pre-consolidation** — the full suite must exit 0 before any S06 or S08 pass lands. *This is
   the operator's "prove what works works before proving the consolidation still works", made
   mechanical.* A red suite blocks a consolidation pass, never an unrelated commit.
3. **scheduled** — full suite on a quiet host, unattended, refusing to start when a local model is
   resident or lanes are in flight; loud on a new red. Daily suffices. The point is that a red is
   found by the machine, not by a fleet outage.
**Non-negotiable:** a stale result renders **UNKNOWN, never green** — the arm that would have
caught the two-day-stale manifest. Bypass allowed, recorded, reasoned (the
`git-commit-mine --explicit` precedent). State-dependent checks quarantined out of tier 1.
**Its own controls:** seeded defect refuses a commit, then restores and passes; seeded defect in
the scheduled tier reports loudly; clean tree passes every tier with no manual step; a bypass with
no reason is refused; an over-age result renders UNKNOWN.

### T790 — S09 spec: module test contracts · blocked on T788
**Pass 0 is the census, and it comes before any test is written.** Operator, 2026-08-23:
*"We've been hacking and monitoring and rehacking and breaking and monitoring some more and
making no progress, often regressing! We don't know what works or doesn't work or why they
existed at all."* Writing tests for 38 modules before knowing which should exist is waste.

**The disorganization, measured 2026-08-23.** Churn without ownership — commits per module and
the count of *distinct task rows* behind them: `tools/runner` 30 commits / **29 rows** / 56
production callers · `bin/subagent` 29 / **26** / 7 · `tools/dispatch_verify.py` 13 / **13** / 3 ·
`bin/dispatch` 9 / 12 / 47. Essentially **one commit per row: no row ever came back.** Twenty-nine
different lanes each patched the fleet's most-invoked file once and left. Three modules
(`runner`, `dispatch`, `managent`) take **128 of 172 commits — 74%** of all tool churn. That is
the mechanism of "rehacking and regressing", and the fix is ownership plus a gate, not more
monitoring.

**13 of 38 modules are invoked by no production file**, and they are three different things
nobody has separated: **hot core** (huge fan-in, most churn, no gate — contracts here first);
**undeclared entry points** (human- or schedule-invoked, so static analysis reads them as dead
while they are load-bearing — `tools/deploy.sh` has 11 test references and zero production
callers; these need a declared role, not deletion); and **actually dead** (invoked by nothing,
referenced by nothing — `bin/weizigo-arena`, `tools/play_oracle.py`, `tools/race-c-prepare.py`,
and `tools/token-backfill.py`, which T746 added *this session* with no caller and no test, and
which is on the dead list on purpose: the census does not exempt its own author).

**Census-method correction (2026-08-23).** The first orphan list was produced by matching
basenames and gave a **false negative** on `tools/window_policy.py`: `bin/subagent:70` does
`import window_policy` — no extension, no path prefix — and calls `family_of`,
`family_cooldown` and `record_override` on **every dispatch**, which is the surviving half of the
operator's own regulation model (appetite + reactive expiring cooldown). It was one careless list
away from being called dead. `tools/directive_policy.py` is likewise live: `bin/dispatch:87`
imports it and calls `evaluate_directives` to enforce pause/kill at dispatch. The import-aware
re-census puts the no-production-caller count at **12, not 13**. Pass 0's census must detect
Python module-name imports, `spec_from_file_location` with a bare name, lazy in-function imports
(`tools/runner._load_token_capture`), path-in-a-variable invocation, and Zig `@import` — and must
state its own blind spots. **No deletion on static reachability alone.**

Pass 0 answers four questions per module — what it is for, who invokes it, when it last did
anything, and whether anyone would notice if it vanished. A module nobody can answer those for is
a deletion candidate. Deletions land as their own rows with reasons, never silently.

**Why:** the operator's module framing, made testable.
**Per module, a contract stating:** owner and purpose in one line · **its public surface** (flags,
env vars, exit codes, files read/written — most of this week's bugs were surface bugs) · unit arms
where there is pure logic · seeded-defect and null-control arms, each shown red before it counts ·
an e2e arm doing the real job · which T789 tier each arm lives in · and a **"would have caught"
line naming a real past incident.** An arm that cannot name one is a candidate for deletion.
**The use-case suite that does not exist today** — five standing scenarios, each on a fixture repo
or scratch store, never the live one:
1. one lane per provider (claude · deepseek · pi/openrouter · ollama-local) dispatched to a
   **verified** close — nonce echoed, deliverables present, row left `in_progress`. Catches the
   exit-0-without-reading-the-bundle lane;
2. co-launch a local model with cloud lanes; assert no cloud lane dies (the 15:19 incident as a test);
3. **the queue drains without a human** — operator: *"I should not wonder why delegation is not
   automatic, it should be tested periodically"*;
4. a race's sealed inputs survive a concurrent repair row, or the mutation is refused;
5. an unrecognized flag is refused, not ignored; a recorded verdict matches the one requested.
**Not** a coverage-percentage exercise; no target test count. Triage the 13 uncovered modules into
*needs a contract* and *should be deleted* — an unused script with no test is a liability.

### T785 — S08 spec: guards stop killing lanes · IN FLIGHT (`claude-opus-5`)
**Why:** the guards are still destroying lanes, and this is the sprint the operator ordered
(*"our tooling and monitors are stupid, panic and suicidal … then we dispatch a sprint to fix this
stupidity. And thoroughly TEST!"*).
**The incident, 2026-08-23 15:19:09** — four Race W judges launched together, all four dead in 88 s:
- **the tenant detector lost a startup race.** T711 subtracts a resident model's footprint so a
  live qwen is not an emergency. It fired and returned **36 MB** for an 18–25 GB tenant, because
  all four lanes launched at once and the MLX engine was not yet resident when sampled. Proof it is
  only the race: re-run solo at 18:0x the same detector read **7,821 MB and rising** and nothing
  died. A correct add-back at 15:19 gives ~24 GB against a 6 GB floor;
- **its control injected the number it should have measured** (`WEIZIGO_HOST_TENANT_RESERVATION_MB`),
  so the arithmetic was proved and the detector never met a real load;
- **the kill was arithmetically futile** — shortfall 6144−5761 = 383 MB; the lanes killed were
  251, 133 and 129 MB; the 18 GB actual consumer was untouched because an Ollama-served model's
  memory belongs to the daemon, not to any fleet member;
- **kill was chosen where refusal was available** — T713 had already shipped *idle is acceptable,
  killing a running lane is not* at the dispatch chokepoint; the running-guard path never learned it.
**Six requirements:** refuse before kill · **no futile kill** (no member with RSS ≥ shortfall ⇒ log
and kill nothing) · charge a model's memory to the lane that asked for it · resolve the tenant
before admitting, not after launching · one arbiter (folds the never-dispatched T712) · sealed race
inputs immutable while a race runs (the Race G defect: a repair row erased all four canaries at
09:41:10Z mid-race, voiding the arm).
**Pass 1 is characterization, not repair** — pin what the guards do today, including the behaviour
just proved wrong, so a later change cannot alter it silently. This is exactly what T711 skipped.
**Smoke tests mandated and named separately from unit arms.** The 15:19 incident would have been
caught by a smoke test and was not caught by a suite of green units.

**Operator ruling to honour: S06 (six fleet scripts → one policy file, one dashboard, one arbiter)
is WANTED, by slow cannibalization, one script at a time, each tested.** Seat recommendation on
disk: **hold S06 until T788 and T789 land.** Consolidating six scripts we cannot currently prove
work, with no gate to say when we have broken them, converts an unstable week into an unstable
month. Concerns recorded for the S06 spec discussion: the arbiter should be the first script
absorbed (every other defect routes through it); the six share no common test harness today, so
"test one by one" needs the harness built in pass 1; and T712 must not be dispatched standalone or
the arbiter gets fixed twice.

## 6. The consolidation rule — measured, not preferred (2026-08-23)

The operator's direction: *"ensure there is one and only one way to dispatch this task"* and
*"see where else there are multiple ways to do the same thing."* Censused:

| one job | ways | what the extra way cost |
|---|---|---|
| close a task | 2 — `done` (gated) vs `lanes --backfill` (ungated) | **9 tasks `done` with no model**, all one timestamp; the value was in the findings the backfill read |
| dispatch an execution | 5 — `bin/dispatch` · `subagent` direct · `runner`→provider · `suggest` · paste-prompt | **159 of 364 executions skipped `bin/subagent`** — no token meter, no read-the-bundle nonce |
| register a task | 2 — `add --bundle` vs `suggest` | `suggest`-then-edit **drops `holds=`** |
| record a kill | 4 stores | 1,476 events; the only tracked store holds **zero** |
| canonicalize a label | 4 copies, 1 control, 1 phantom control | a serving tag reached the ledger; ox-alpha dropped silently |
| set a verdict | 2 flag names (`done --status`, `amend --verdict`) | a `pass-with-findings` silently recorded as `pass` |
| map short names | 2 tables | the registry itself says "no second mapping anywhere" |
| run tests | 6 entry points | nothing runs any of them automatically |
| name a task type | 2 taxonomies | prose in both docs still unmigrated |
| store a task | 2 files | a retired task read as deleted until the archive was checked |

**The pattern is not sloppiness.** Every case is a gated primary path plus an ungated convenience
path added later under time pressure — and the convenience path is always the one that loses
data, because the gate is where the data is demanded.

**The rule for S06 and every consolidation after it:** *one door per job. A bulk or convenience
path may exist, but it CALLS the gated function — it never reimplements it.* The nine missing
models are one function call.

Also load-bearing, and the reason "add a check" is the wrong instinct: **the gates mostly exist
and work.** Landmark declaration is required at registration (T682) and brief compliance is
**94/94 = 100% for T700+**, against 46% for T500–T699 and 0% before T300. The gate arriving is
visible in the data. The failures are second doors, not missing locks.
